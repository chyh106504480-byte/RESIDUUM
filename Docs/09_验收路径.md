# 验收路径 —— 从空场景到跑通一局

> 每次要在 Unity 里验收核心循环时照这份走。菜单全在 `Residuum` 下。
> **顺序不能乱**，第五步的前置检查依赖前面全部完成。

---

## 一、四个装配菜单 + 一步手工

### 1. `Residuum/搭建玩家装配`

生成玩家 + 相机 + `PlayerInteractor`，注入输入资产。

场景已有玩家时不重建，只补挂交互器。

### 2. `Residuum/创建三种鬼资产`

在 `Assets/_Project/ScriptableObjects/Ghosts/` 生成
`GhostDef_Spirit` / `GhostDef_Wraith` / `GhostDef_Poltergeist`。

数值照 GDD 1.2 节填好，已存在则跳过不覆盖。
Console 会打一条**白色**信息「已创建鬼定义资产：…」，那是成功日志不是警告。

### 3. `Residuum/搭建鬼装配`

生成 `Ghost`（`NavMeshAgent` + `GhostAI` + 占位可见体）与四个待摆放的巡逻点。

**会打一条黄色警告**：「鬼房中心暂用 Ghost 自身位置、半径暂用 4」。
**这是预期的**——鬼房数据在回合开始时由 `GameManager` 注入，装配工具只能给占位值。
不用处理。

### 4. 手工：建 `RoomManager` 与 `RoomVolume`

**这一步必须在第五步之前**，否则第五步会拦下并报
「场景中没有 RoomManager」。

**建 RoomManager**：
1. Hierarchy 空白处右键 → `Create Empty`，命名 `RoomManager`
2. `Add Component` → `Room Manager`

**每个房间建一个 RoomVolume**：
1. `Create Empty`，命名照 `BLK_Room_厨房` 之类
2. `Add Component` → `Box Collider`，**勾上 `Is Trigger`**
3. 调 `Size` 罩住房间（见下方尺寸要求）
4. `Add Component` → `Room Volume`
5. 填「房间中文名」，**挑几间勾上「可作为鬼房候选」**

**最少三间就能验收**：一间鬼房候选 + 两间普通房。不必一次摆全，
`RoomManager` 是运行时自动收集场景中全部 `RoomVolume` 的，之后加房间不用改代码。

### 5. `Residuum/搭建回合装配`

生成 `RoundSetup`，其下 `GameManager`、`HuntController`、`ExitZone`、`SafeZone`，
并把九个引用一次连好。

**出口与安全区只是占位**，生成在玩家当前位置。手动挪：
- `ExitZone` → 一楼大门口
- `SafeZone` → 一楼 Lobby，并调大到罩住整层

### 6. `Residuum/搭建测试台`（可选）

生成一扇门与一支手电，用于单独验交互与道具槽。

## 二、RoomVolume 盒子该多大

代码对这个 Collider 有三处用途，决定了尺寸要求：

| 用途 | 影响 |
|---|---|
| 玩家进出检测 | 只要玩家在盒子里就算在这间房，**粗一点没关系** |
| 鬼的落脚点 | `GetRandomPointInside` 在盒子 XZ 平面随机取点、取**底面高度**，再吸附到导航网格 |
| 鬼房半径 | `GameManager` 取 `bounds.extents.magnitude`（半对角线），给鬼影书判定用 |

**因此三条要求：**

1. **不要伸出墙外。** 随机点落到墙那边，吸附后鬼会被扔进隔壁房间或走廊。
   XZ 方向贴到墙内表面即可，差十几厘米无所谓。
2. **不要做太大。** 半对角线已经比房间边长大，再放大会让鬼影书在走廊里也判定成
   「在鬼房内」，证据条件形同虚设。
3. **底面压在地板上。** 随机点取的是盒子底面高度，盒子悬空会让
   `NavMesh.SamplePosition` 找不到网格。

**不需要完美贴合。**高度到 2.5 米就够（玩家和鬼都在地面附近），
但**别和邻居房间重叠**——重叠区域里 `CurrentPlayerRoom` 判定会飘。

`RoomVolume` 有 Gizmos，Scene 视图里能看到边界与中文名，鬼房候选颜色不同。

## 三、按 Play 跑一局

UI 尚未完成，用三个调试键（`#if UNITY_EDITOR` 包裹，只在编辑器生效）：

| 键 | 作用 |
|---|---|
| `F11` | 一键集齐三种证据，跳过取证流程 |
| `F9` | 强制触发猎杀，不必等理智掉到 50 以下 |
| `F10` | 直接结束回合，看结算评级 |

**开局应当看到**：Console 输出选中的鬼种名与鬼房名，鬼被传送到鬼房并开始巡逻。

**结算四级**：
- `Perfect` —— 判定正确 + 集齐 2 项证据 + 理智 > 30
- `Success` —— 判定正确
- `Survived` —— 判定错误或未判定
- `Died` —— 被猎杀

## 四、灰盒阶段的预期警告（都不用处理）

这几条是**正常状态**，不是缺陷。它们用黄色警告而非红色错误，就是为了不挡住验收：

- 「第 N 槽已有道具但未指定手持模型」 —— 灰盒没有手持模型网格
- 「未注入脚印预制体」 —— 灰盒没有脚印贴花
- 「鬼房中心暂用 Ghost 自身位置」 —— 装配工具的占位值，回合开始时会被覆盖

**红色错误一律要处理**，它们都指名道姓说明缺什么、该先执行哪个菜单。
