# 交接给 Claude Code

## 怎么用这份文件

在 `~/RESIDUUM` 目录下开一个新的 Claude Code 会话，把下面「交接提示词」整段贴进去。
`CLAUDE.md` 会自动加载，所以这段提示词只负责**交接动作本身**，不重复它的内容。

之后的日常不需要再贴任何东西，直接用四条命令：
`/task`（写任务包）→ `/dispatch`（派活）→ `/review`（终审）→ `/contract`（加契约）。

## 交接提示词

```
从现在起你接管《残响》RESIDUUM 的日常推进。之前这套协作跑在 Claude 的另一个
会话里，现在整体交到你这边，仓库里的一切就是全部交接物——没有别的口头上下文。

先读 CLAUDE.md，那是你的岗位说明书，重点是第 2 节（你不写模块代码）和
第 5 节（终审规则）。再读 AGENTS.md，那是 Codex 的约束，你要知道它被怎么管着。

然后不要凭记忆判断进度，跑这三条自己看：

  git -C ~/RESIDUUM log --oneline -12
  git -C ~/RESIDUUM status --short
  python3 ~/RESIDUUM/tools/codexctl/codexctl.py list

看完给我一份接管简报，四段，不要长：

1. 你理解的自己的位置和边界，用你自己的话说一遍（我要确认你没把自己当成执行者）
2. 仓库当前实际状态：分支、未推送提交数、工作区是否干净、哪些任务已闭环
3. 关键路径上的下一个任务是什么，为什么是它
4. 有什么是仓库里没写清楚、你需要我拍板的

简报之后停下等我，先别动手。
```

## Claude Code 侧的四条命令

| 命令 | 什么时候用 |
|---|---|
| `/task T04 房间系统与鬼房` | 要开新模块，先把需求写成 Codex 能执行的任务包 |
| `/dispatch T04` | 任务包写好了，派给 Codex 跑完整链路 |
| `/review T04` | codexctl 跑完了，做终审 |
| `/contract OnXxx(...)` | Codex 申请新事件，由 Claude 决定加不加、怎么加 |

四条命令的正文在 `.claude/commands/` 下，可以直接改。

## 分工快照

```
Henry     定方向、拍板、在 Unity 里验行为        ← 唯一能说"行为正确"的人
Claude    契约 / 任务包 / 调度 / 终审            ← 不写模块代码
Codex     写模块代码                            ← 受 AGENTS.md 约束
codexctl  闸门 + 编译 + 打回重修 + 结构化自审     ← 机器关卡，不信自述
```

**三个人的判断冲突时的优先级**：Henry 的行为验收 > 编译结果 > 静态闸门 > Codex 自审。
