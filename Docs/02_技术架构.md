> 这份文档的唯一目的：**让 Codex 生成的每个模块都能独立编译、直接落位、互不冲突。**
> 在给 Codex 派任何任务之前，先把本文档 §1–§3 完整粘贴给它作为上下文。

## 2. 目录结构（强制）

所有自写内容放 `Assets/_Project/`，与第三方素材彻底隔离。**这条规则救命**——素材包升级或删除时不会带走你的代码。

```
Assets/
├── _Project/
│   ├── Scripts/
│   │   ├── Core/          GameManager, GameState, GameEvents, RoundConfig
│   │   ├── Player/        PlayerController, PlayerSanity, PlayerHiding
│   │   ├── Ghost/         GhostAI, GhostDefinition(SO), IGhostBehaviour, HuntController, GhostEventSystem
│   │   ├── Evidence/      EvidenceType, EvidenceManager, EMFReader, UVLight, GhostWritingBook, Fingerprint
│   │   ├── Items/         ItemBase, IHoldable, Flashlight, ItemSlotSystem, ThrowableProp
│   │   ├── World/         PlayerInteractor, Door, RoomVolume, HidingSpot, InteractableBase, RoomManager
│   │   ├── UI/            HUDController, JournalUI, ResultScreen, CrosshairPrompt
│   │   └── Audio/         AudioDirector, FootstepPlayer, ScareCue
│   ├── Prefabs/           Player/ Ghost/ Items/ World/ UI/
│   ├── ScriptableObjects/ Ghosts/ (Spirit.asset, Wraith.asset, Poltergeist.asset)
│   ├── Scenes/            Main.unity, _Sandbox.unity  ← Sandbox 是灰盒测试场
│   ├── Art/               Materials/ Models/ Textures/ VFX/
│   ├── Audio/             SFX/ Ambience/ Music/
│   └── Settings/          URP Assets, Input Actions, Lighting Settings
├── StarterAssets/         ← 第三方，不改
├── ThirdParty/            ← 所有下载的免费素材放这里
└── Docs/                  ASSET_LICENSES.md ← 每导入一个素材加一行
```

**命名规范**
- 脚本 / 类：`PascalCase`，文件名 == 类名
- 私有字段：`_camelCase`；序列化私有字段用 `[SerializeField] private float _walkSpeed;`
- 公开属性：`PascalCase { get; private set; }`
- 事件：`OnXxx`
- 命名空间：**全部使用 `Residuum.<模块>`**，如 `namespace Residuum.Ghost`

## 3. 架构铁律（这一节决定项目会不会崩）

### 铁律一：事件总线解耦

**问题**：Codex 分模块生成代码时，如果 `PlayerSanity` 直接引用 `GhostAI`，两个模块必须同时存在才能编译，一个改动就连锁崩溃。

**解法**：所有跨模块通信走静态事件总线 `GameEvents`。**先建这个文件，再派任何其他任务。**

```csharp
// Assets/_Project/Scripts/Core/GameEvents.cs
using System;
using UnityEngine;

namespace Residuum.Core
{
    /// <summary>
    /// 全局事件总线。所有跨模块通信必须通过这里，禁止模块之间直接持有引用。
    /// 订阅方务必在 OnDisable 中取消订阅，避免场景重载时的空引用。
    /// </summary>
    public static class GameEvents
    {
        // ── 回合流程 ──
        public static event Action OnRoundStart;
        public static event Action<RoundResult> OnRoundEnd;

        // ── 理智 ──
        public static event Action<float> OnSanityChanged;        // 参数: 当前理智 0-100
        public static event Action OnSanityCritical;              // 首次跌破 50%

        // ── 猎杀 ──
        public static event Action<float> OnHuntStart;            // 参数: 持续秒数
        public static event Action OnHuntEnd;
        public static event Action OnPlayerCaught;

        // ── 证据 ──
        public static event Action<EvidenceType> OnEvidenceFound;

        // ── 鬼的活动 ──
        public static event Action<Vector3> OnGhostInteract;      // 鬼与物体互动的位置
        public static event Action<Vector3> OnGhostEvent;         // 显形/惊吓事件位置

        // ── 玩家状态 ──
        public static event Action<bool> OnHidingChanged;

        // ── 触发器（只允许对应模块调用） ──
        public static void RaiseRoundStart()                 => OnRoundStart?.Invoke();
        public static void RaiseRoundEnd(RoundResult r)      => OnRoundEnd?.Invoke(r);
        public static void RaiseSanityChanged(float v)       => OnSanityChanged?.Invoke(v);
        public static void RaiseSanityCritical()             => OnSanityCritical?.Invoke();
        public static void RaiseHuntStart(float d)           => OnHuntStart?.Invoke(d);
        public static void RaiseHuntEnd()                    => OnHuntEnd?.Invoke();
        public static void RaisePlayerCaught()               => OnPlayerCaught?.Invoke();
        public static void RaiseEvidenceFound(EvidenceType e)=> OnEvidenceFound?.Invoke(e);
        public static void RaiseGhostInteract(Vector3 p)     => OnGhostInteract?.Invoke(p);
        public static void RaiseGhostEvent(Vector3 p)        => OnGhostEvent?.Invoke(p);
        public static void RaiseHidingChanged(bool h)        => OnHidingChanged?.Invoke(h);
    }

    public enum RoundResult { Perfect, Success, Survived, Died }
}
```

### 铁律二：鬼是数据，不是代码

三种鬼**不写三个类**。写一个 `GhostAI` + 一个 `GhostDefinition` ScriptableObject。
好处：你（设计师）在 Inspector 里调数值，不需要碰代码，也不需要重新麻烦 Codex。

```csharp
// Assets/_Project/Scripts/Ghost/GhostDefinition.cs
using UnityEngine;
using Residuum.Evidence;

namespace Residuum.Ghost
{
    [CreateAssetMenu(fileName = "GhostDef", menuName = "Residuum/Ghost Definition")]
    public class GhostDefinition : ScriptableObject
    {
        [Header("身份")]
        public string ghostName = "怨灵";
        public string displayNameEN = "Spirit";
        [TextArea] public string journalDescription;

        [Header("证据组合（必须恰好 2 项）")]
        public EvidenceType[] evidences = new EvidenceType[2];

        [Header("移动")]
        public float walkSpeed = 1.6f;
        public float huntSpeed = 1.7f;
        public bool leavesFootprints = true;      // 幽影 = false

        [Header("猎杀")]
        public float huntDuration = 25f;
        public float huntCooldown = 25f;
        public float sanityDrainMultiplier = 1f;  // 骚灵 = 1.5

        [Header("特殊行为")]
        public bool canSprintBurst = false;       // 幽影 = true
        public float sprintBurstInterval = 6f;
        public bool massThrowOnHunt = false;      // 骚灵 = true
        public float interactFrequency = 1f;      // 骚灵 = 2.0

        void OnValidate()
        {
            if (evidences != null && evidences.Length != 2)
                Debug.LogWarning($"[{name}] 证据数量必须恰好为 2 —— 否则会破坏推理表的唯一性。");
        }
    }
}
```

### 铁律三：接口先行

Codex 写实现前，接口必须已存在于工程中。核心接口只有三个：

```csharp
// Assets/_Project/Scripts/World/IInteractable.cs
namespace Residuum.World
{
    public interface IInteractable
    {
        string PromptText { get; }        // 准星提示，如 "[E] 开门"
        bool CanInteract { get; }
        void Interact(GameObject interactor);
    }
}

// Assets/_Project/Scripts/Items/IHoldable.cs
namespace Residuum.Items
{
    public interface IHoldable
    {
        string ItemName { get; }
        void OnEquip();
        void OnUnequip();
        void OnPrimaryUse();             // 左键 / F
    }
}

// Assets/_Project/Scripts/Evidence/IEvidenceSource.cs
namespace Residuum.Evidence
{
    public interface IEvidenceSource
    {
        EvidenceType ProvidedEvidence { get; }
        bool TryCollect(out EvidenceType evidence);
    }
}

// Assets/_Project/Scripts/Evidence/EvidenceType.cs
namespace Residuum.Evidence
{
    public enum EvidenceType { None = 0, EMF5 = 1, UVFingerprint = 2, GhostWriting = 3 }
}
```

### 铁律四：一个任务一个文件

给 Codex 的每个任务**只产出 1–2 个 .cs 文件**。原因：
- 出错时定位快
- 队友 code review 成本低
- Git 冲突概率趋近于零

### 铁律五：所有可调数值必须 `[SerializeField]` 暴露

作为总设计师，你的核心工作是**调手感**。任何硬编码的数字都是在剥夺你的设计权。给 Codex 的每个 prompt 结尾都加一句：
> "所有影响手感与平衡的数值必须用 `[SerializeField] private` 暴露到 Inspector，并加 `[Tooltip]` 中文说明，禁止硬编码常量。"

```

                        │ GameEvents  │  ← 所有人只依赖它
                        └──────┬──────┘
         ┌────────────┬────────┼────────┬────────────┐
         │            │        │        │            │
   ┌─────▼─────┐ ┌────▼───┐ ┌──▼───┐ ┌──▼────┐ ┌────▼────┐
   │  Player   │ │ Ghost  │ │Items │ │Evidence│ │   UI    │
   │Controller │ │  AI    │ │      │ │Manager │ │ Journal │
   │  Sanity   │ │ Hunt   │ │      │ │        │ │  HUD    │
   └───────────┘ └────────┘ └──────┘ └────────┘ └─────────┘
         │            │        │        │            │
         └────────────┴────────┼────────┴────────────┘
                        ┌──────▼──────┐
```

**唯一例外**：`GameManager` 可以持有各系统引用（做初始化与回合控制）。其他所有模块**只能**通过 `GameEvents` 通信。

## 5. 你（总设计师）的 Codex 工作流

```
① 从 03_Codex任务包.md 复制一个任务的完整 prompt
② 首次对话时，先粘贴本文档的 §2 目录结构 + §3 铁律（含 GameEvents 和接口代码）
③ 让 Codex 输出完整 .cs 文件
④ 你审查三件事：
     ✓ 有没有直接引用别的模块（应该只用 GameEvents）
     ✓ 数值有没有 [SerializeField] 暴露
     ✓ 命名空间对不对
⑤ 落位到指定路径 → Unity 编译 → 在 _Sandbox.unity 里单独测这个模块
⑥ 通过 → git commit，一个模块一个 commit
⑦ 不通过 → 把编译错误原文贴回 Codex 让它修，不要自己硬改
```

> **审查比生成重要。** Codex 一天能写完这个项目的所有代码，但只有你能判断"手感对不对"。把时间花在第 ④ 步和第 ⑤ 步。

## 6. 常见坑（提前写下来，省几小时）

| 坑 | 解法 |
|----|------|
| NavMesh 烘焙不到室内地板 | 用 **AI Navigation 包的 NavMeshSurface 组件**，不要用旧版 Navigation 窗口；地板必须标记 Static 或在 Surface 的 Collect Objects 中包含 |
| Starter Assets 的输入与自定义输入冲突 | 不要改 `StarterAssets` 里的文件；复制一份 Input Actions 到 `_Project/Settings/` 再扩展 |
| URP 下手电筒没有软阴影/体积感 | URP Asset 里开 Additional Lights → Shadows；体积光用 Shader Graph 做圆锥半透明网格伪造，别上真体积光（性能陷阱） |
| 事件订阅未取消导致场景重载后报空引用 | 每个订阅了 `GameEvents` 的类，`OnEnable` 订阅、`OnDisable` 必须取消 |
| 鬼穿墙 / 卡门 | 门要么设为 NavMeshObstacle + Carve，要么用 OffMeshLink；二选一，别混用 |
| 猎杀时手电筒还亮着 | `Flashlight` 订阅 `OnHuntStart`，强制进入闪烁协程 |
