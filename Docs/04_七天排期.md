# 《残响》七天排期与分工

> 团队：Henry（总设计师）+ 1 名队友（Day 0 pitch 后确定）+ Codex
> 时间：Day 0 = 8月22日（周六，pitch 当天） → Day 7 = 8月29日（周六，交付）

---

## 核心原则

**1. 灰盒可玩优先，Day 5 之前不碰美术。**
一个用白盒子做的、能完整跑通循环的游戏，永远好过一个画面精美但走不到结算的 Demo。

**2. 每天结束时项目必须处于"能运行"状态。**
不允许把编译不过的代码留到第二天。这是硬规矩。

**3. 关键路径优先。**
T01→T02→T04→T09→T10→T15 这条链上的任务，永远排在美术、音频、UI 之前。

## 分工方案（Day 0 确定队友能力后二选一）

### 方案 A —— 队友会 Unity / 会写代码

| Henry（总设计师） | 队友（系统与表现） |
|------|------|
| 关键路径全部模块的 Codex 派发与审查（T01–T12, T15） | UI 全套（T13 笔记本、T14 HUD、T16 结算） |
| 地图搭建、灯光、美术整合 | 音频全套（T17）+ 素材收集 |
| 数值平衡与手感调优 | 测试、Bug 记录、Build |
| Pitch、演示视频、文档 | |

### 方案 B —— 队友不熟 Unity

| Henry | 队友 |
|------|------|
| 所有代码模块的 Codex 派发与集成（T01–T17） | **素材总管**：搜集所有免费模型/音效/材质，整理分类，写许可文档 |
| 地图、灯光、美术、数值 | **测试与记录**：每天玩一遍写测试报告，记录 Bug 清单 |
| | **文档与演示**：整理 GDD、做 pitch 幻灯片、剪演示视频 |
| | **UI 摆放**：按 Codex 输出的层级说明在 Canvas 里手动搭 UI（不需要写代码） |

> 方案 B 完全可行。**素材收集 + 测试 + 文档 + 视频**这四件事本身就能占满一个人一周，而且是你最不该花时间的事。

## 每日站会（10 分钟，固定时间）

三个问题：

1. 昨天完成了什么？（对照任务包的 ✅ 验收标准，通过才算完成）
2. 今天要完成什么？
3. 有什么卡住了？**卡住超过 2 小时必须换方案或砍需求，不许硬扛。**

## Git 规范

- 分支：`main`（永远可运行）+ 各自的 `feat/xxx` 分支
- 一个模块一个 commit，格式：`feat(ghost): T09 鬼AI状态机` / `fix(ui): 笔记本 Tab 键冲突`
- **每天收工前必须 merge 回 main 并确认能运行**
- `.unity` 场景文件容易冲突：约定**同一时间只有一人编辑主场景**，另一人在自己的测试场景里工作
