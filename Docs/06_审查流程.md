# 《残响》代码审查流程

> 分工：**Codex 写 → Codex 自审 → Henry 在 Unity 验证 → Claude 终审**
> 这份文档定义中间两步怎么做才有效。

---

## 零、开工前：把地基建进工程（只做一次）

解压 `Foundation.zip`，把 `Scripts/` 下的 6 个文件按原路径放进 `Assets/_Project/Scripts/`：

```
Assets/_Project/Scripts/Core/GameEvents.cs
Assets/_Project/Scripts/Core/RoundResult.cs
Assets/_Project/Scripts/Evidence/EvidenceType.cs
Assets/_Project/Scripts/Evidence/IEvidenceSource.cs
Assets/_Project/Scripts/World/IInteractable.cs
Assets/_Project/Scripts/Items/IHoldable.cs
Assets/_Project/Scripts/Ghost/GhostDefinition.cs
```

确认 Unity 编译通过（Console 无红字），然后 `git commit -m "chore: 架构契约地基"`。

### ⚠️ 这七个文件是不可协商的契约

**任何 Codex 任务都不得修改它们。** 如果 Codex 生成的代码要求改动 `GameEvents` 的事件签名，说明它误解了架构 —— 把代码贴回来我判断，不要让它改。

需要新增事件时找我加，我会保证签名与已有模块兼容。

## 一、给 Codex 的标准 Prompt 结构

每个任务的完整 prompt = 四段拼接：

```
【第 1 段】项目上下文（每个新会话贴一次）
   → 02_技术架构.md 的 §2 目录结构 + §3 铁律
   → Foundation 里 GameEvents.cs / 四个接口 / GhostDefinition.cs 的完整代码

【第 2 段】通用前缀
   → 03_Codex任务包.md 顶部的「通用前缀」

【第 3 段】具体任务
   → 03_Codex任务包.md 中某一个 T## 的 📋 Prompt

【第 4 段】自审要求
   → 本文档 §2 的清单，原文粘贴
```

**一次只做一个任务。** 合并任务的代价是出错时无法定位。

## 二、Codex 自审清单（原文粘贴到每个 prompt 末尾）

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【交付前自审】

在给出最终代码之前，请你逐条检查下列 18 项，并在代码之后
以表格形式输出自审结果（每项标注 通过 / 已修正 / 不适用）。
如果某项检查发现了问题，请先修正代码再输出。
不要跳过这一步，也不要笼统地说「已检查」。

── 架构合规 ──
1. 除 Residuum.Core、Residuum.Evidence 的枚举与接口外，本文件是否
   using 或引用了其他模块的具体类？如果有，改为通过 GameEvents 通信
   或通过 [SerializeField] / UnityEvent 由 Inspector 注入。
2. 命名空间是否为 Residuum.<指定模块名>？
3. 是否修改了 GameEvents 或任何接口的定义？（绝对禁止）
4. 文件名是否与主类名完全一致？

── 生命周期 ──
5. 每一个 GameEvents 的订阅，是否在 OnEnable 中订阅、OnDisable 中取消？
   两者是否严格配对、数量相等？
6. 所有 StartCoroutine 启动的协程，是否在 OnDisable 中停止？
7. 是否存在 OnDestroy 时未清理的引用或计时器？

── Unity 6 API ──
8. 是否使用了 FindObjectOfType / FindObjectsOfType / FindFirstObjectByType？
   Unity 6.x 这三个都已废弃（FindFirstObjectByType 依赖 instance ID 排序）。
   单个用 FindAnyObjectByType<T>()；
   批量用 FindObjectsByType<T>(FindObjectsInactive.Include)，
   不要传 FindObjectsSortMode —— 带该参数的重载同样已废弃。
9. 是否使用了 Rigidbody.velocity？Unity 6 已改名为 linearVelocity。
10. 是否使用了旧版输入 Input.GetKey / Input.GetAxis / Input.mousePosition？
    本项目使用 New Input System (UnityEngine.InputSystem)。
11. 是否使用了 Cinemachine 2.x 的类名（如 CinemachineVirtualCamera）？
    本工程装的是 Cinemachine 3.1.7，已改名为 CinemachineCamera。
12. 是否在 Update 中重复调用 Camera.main？应在 Awake 中缓存。
    协程中的 WaitForSeconds 是否在循环内反复 new？应缓存为字段。

── 设计师可调性 ──
13. 是否存在任何硬编码的数值常量（速度、时长、概率、距离、角度）？
    全部必须改为 [SerializeField] private 字段。
14. 每一个 [SerializeField] 字段是否都有 [Tooltip("中文说明")]？
15. 数值字段是否给了合理默认值（与设计文档一致）？

── 健壮性 ──
16. 所有 GetComponent / 引用字段，使用前是否做了 null 检查？
    关键依赖缺失时是否用 Debug.LogError 明确报出，而不是静默失败？
17. 是否有除零、数组越界、负数开方等风险？
18. 代码是否完整（没有 "..." 省略、没有 TODO 占位、可直接编译）？

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

> **为什么要它输出表格**：只说"请自查"，模型会回答"已检查，无问题"。要求逐项标注结果，它必须真的走一遍，且你能一眼看出它在哪一项撒谎。

## 三、Henry 在 Unity 里的验证（30 秒，别跳过）

代码落位后，按顺序做三件事：

1. **看 Console** —— 红字（error）必须为零；黄字（warning）里凡是含 `obsolete` 的都要记下来
2. **在 `_Sandbox.unity` 里单独测这个模块** —— 不要在主场景测，主场景变量太多
3. **看 Inspector** —— 数值字段是不是都露出来了、Tooltip 有没有中文

**通过 → `git commit`，一个模块一个 commit。**
**不通过 → 进入第四步。**

## 四、交给我终审时，请提供这三样

我审得准不准，取决于你给的信息全不全。最理想的一次提交长这样：

```
【任务】T03 道具槽 + 手电筒

【Codex 自审结果】
（粘贴它输出的那张 18 项表格）

【代码】
（粘贴完整的 .cs 文件全文，两个文件都要）

【Unity 中的实际情况】
- Console：0 error / 2 warning（内容：...）
- 运行表现：切槽正常，但手电筒按 F 没反应
- 我期望的是：...
```

第三部分最重要。**Codex 的自审只能发现"代码写得对不对"，发现不了"手感对不对"和"和别的模块拼不拼得上"** —— 后两件事才是我要看的。

如果只是编译报错，其实不用找我，直接用任务包末尾的调试模板贴回 Codex 更快。找我的时机是：**行为不符合预期、模块之间对不上、或者你不确定某个写法会不会在后面埋雷。**

## 五、我的审查维度（你可以据此判断我在看什么）

| 维度 | 我在找什么 |
|------|-----------|
| **契约一致性** | 事件签名、接口实现、命名空间是否与地基和其他模块对得上。这是 Codex 最容易出错的地方，也是最晚才暴露的错误 |
| **跨模块耦合** | 有没有偷偷 `GetComponent<其他模块的类>()`。Codex 很爱这么干，因为它"更直接" |
| **生命周期** | 订阅/取消是否配对，协程有没有泄漏。表现为「玩久了越来越卡」或「重进播放模式后事件触发两次」 |
| **数值是否合理** | 不只是能不能跑，而是这个默认值放进游戏里手感对不对 |
| **未来的雷** | 这个写法在接入第 10 个模块时会不会炸。这是自审清单查不出来的部分 |

## 六、Codex 常见失败模式（提前认识，省时间）

| 症状 | 根因 | 处理 |
|------|------|------|
| 它自己定义了一个 `GameEvents` | 上下文没贴够，它以为要从零建 | 重贴地基代码，明确说「这些已存在，直接用」 |
| 事件签名和我给的不一样 | 它"优化"了接口 | 贴回去，明确禁止改契约 |
| 代码里出现 `// TODO: implement` | 任务描述太长，它偷懒 | 拆成两个更小的任务 |
| 用了 `FindObjectOfType` | 训练数据里旧 API 占多数 | 自审清单第 8 项会拦住 |
| 数值全硬编码在代码里 | 默认习惯 | 自审清单第 13 项 |
| 一次给了五个文件 | 它想一步到位 | 明确要求「只输出我指定的文件」 |
| 反复修改同一个 Bug 修不好 | 上下文被历史对话污染 | **开新会话重来**，别在旧会话里死磕 |

> 最后一条特别重要。同一个会话里改超过 3 轮还没好，就是新开会话的信号 —— 沉没成本不值得。
