## 目标

把撤离从「走进出口区域自动结束」改成「**在大堂玻璃门上按 E → 弹窗问是否撤离
→ 选是才结束**」。

撤离是整局唯一不可逆的动作，碰一下门就结束太粗暴，必须有一次确认。

## 契约已就位

```csharp
/// 玩家在出口门上按了交互键，请求撤离。这不是撤离本身。
public static event Action GameEvents.OnEvacuatePromptRequested;
public static void GameEvents.RaiseEvacuatePromptRequested();
```

**不要自己往 GameEvents.cs 加任何东西。**

`GameManager.RequestEvacuate()` 已经是 public 的，它自己会检查回合是否进行中、
是否正在猎杀。**不要改 GameManager 的任何一行。**

## 要做两个文件

### 一、`Assets/_Project/Scripts/World/ExitDoor.cs`，命名空间 `Residuum.World`

实现 `Residuum.Core.IInteractable`。挂在大堂那扇玻璃门上。

```csharp
[Tooltip("平时的交互提示")]
[SerializeField] private string _promptText = "[E] 撤离";

[Tooltip("猎杀期间的提示，此时不能撤离")]
[SerializeField] private string _huntingPromptText = "猎杀期间无法撤离";
```

- 订阅 `GameEvents.OnHuntStart` / `OnHuntEnd` 维护一个 `_isHunting` 标志，
  另外订阅 `OnRoundStart` 把它复位为 false。
  `OnEnable` 订阅、`OnDisable` 取消订阅，两边都要写
- `CanInteract` —— `!_isHunting`
- `PromptText` —— 猎杀中返回 `_huntingPromptText`，否则 `_promptText`
- `Interact(GameObject)` —— 只做一件事：`GameEvents.RaiseEvacuatePromptRequested()`。
  **不要直接调 `GameManager.RequestEvacuate`**，那就没有确认环节了

**`Awake` 里要检查同一个 GameObject 上有没有 `Door` 组件**，有就
`Debug.LogError` 说明两者不能共存并让 `CanInteract` 恒为 false。
理由：两者都实现 `IInteractable`，`PlayerInteractor` 用
`GetComponentInParent<IInteractable>()` 取，同时存在会随机取到一个，
表现为「有时候按 E 是开门有时候是撤离」，极难排查。
`Door` 和 `ExitDoor` 同属 `Residuum.World`，直接引用类型不算跨模块。

### 二、`Assets/_Project/Scripts/UI/EvacuateConfirmUI.cs`，命名空间 `Residuum.UI`

uGUI + TextMeshPro。所有界面引用 `[SerializeField]` 注入，
**不要在代码里创建任何 UI 对象**（搭建界面是下一个任务）。

```csharp
[SerializeField] private GameObject _panelRoot;          // 开局隐藏
[SerializeField] private TMPro.TextMeshProUGUI _messageLabel;
[SerializeField] private UnityEngine.UI.Button _confirmButton;
[SerializeField] private UnityEngine.UI.Button _cancelButton;

[SerializeField] private string _message = "确定要撤离吗？离开后本局结束。";

[Tooltip("在 Inspector 里连到 GameManager.RequestEvacuate")]
public UnityEngine.Events.UnityEvent onEvacuateConfirmed;
```

行为：

- 订阅 `GameEvents.OnEvacuatePromptRequested` → 显示弹窗
- 显示时 `GameEvents.RaiseLookSuspendedChanged(true)`，隐藏时 `false`。
  **不要自己写 `Cursor.lockState` / `Cursor.visible`**，光标只有
  `PlayerController` 一个主人，两处同时写必然打架
- 确认按钮 → 先隐藏弹窗（含 `RaiseLookSuspendedChanged(false)`），
  **再** `onEvacuateConfirmed?.Invoke()`。顺序不能反：结算界面在回合结束后
  要禁用 `PlayerController`，弹窗必须先把视角还回去
- 取消按钮 → 只隐藏
- 订阅 `GameEvents.OnHuntStart`、`OnRoundStart`、`OnRoundEnd`，
  收到任意一个都强制隐藏（猎杀开始时玩家必须立刻恢复控制）
- `OnDisable` 里若弹窗还开着也要隐藏，否则组件被禁用后玩家的视角永远挂起

**`_panelRoot` 不允许是本组件所在的 GameObject 或它的祖先**，
`Awake` 里检出这种配置要报错并禁用组件——否则弹窗一隐藏，
组件就收不到后续事件了。参照 `ResultScreenUI` 与 `JournalUI` 里的同类校验。

`_message` 写进 `_messageLabel`。两个按钮的文字由搭建工具填，本组件不管。

## 一个已知取舍，不用解决

判定笔记本开着的时候再打开撤离弹窗，关掉弹窗会把视角还回去，
而笔记本还开着。`OnLookSuspendedChanged` 是布尔量不是引用计数。
玩家按一下 Tab 就能恢复，Day 5 不值得为这个改契约。
**在最终回复里记一笔即可，不要动手改。**

## 验收标准

Henry 会把 `ExitDoor` 挂到大堂玻璃门上、清空 `GameManager` 的
`Exit Zone`，然后点：

1. 编译通过，`git diff` 只有新增的两个 `.cs`（及其 meta）
2. 瞄准玻璃门，准星下方出现「[E] 撤离」
3. 按 E，屏幕中央弹出确认框，鼠标光标出现，**WASD 依然能走**
4. 点「取消」，弹窗消失，视角恢复，回合继续
5. 再按 E 点「确认」，回合结束，结算面板弹出
6. 按 P 强制猎杀，瞄准玻璃门提示变成「猎杀期间无法撤离」，按 E 无反应
7. 弹窗开着时触发猎杀，弹窗立刻自动关闭，玩家恢复视角控制
8. 把 `Door` 和 `ExitDoor` 挂在同一个物体上，进 Play 时控制台报错
   说明两者不能共存，且按 E 无反应
9. 清空 `_panelRoot` 或把它拖成组件自己所在的物体，进 Play 时报错，
   不抛空引用
