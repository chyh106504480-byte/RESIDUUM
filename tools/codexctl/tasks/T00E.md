## 背景：这不是代码问题，是工程配置问题

**先读完这一节再动手。上一轮你已经正确地指出「16 条错误的根因是程序集缺失，
不是 C# 代码」——你是对的。这个任务就是去修那个根因，并且明确授权你修改工程配置。**

诊断结论与证据：

1. `Packages/manifest.json` 的 `dependencies` 里**一个 `com.unity.modules.*` 条目都没有**，
   从初次签入 `5d58674` 起就是如此（`git log -- Packages/manifest.json` 三个提交全是 0 条）。
2. 失败编译日志中 `Assembly-CSharp.rsp` 的引用集里，
   **凡是以 `com.unity.modules.*` 包形式提供的引擎模块全部缺席**：
   没有 `UnityEngine.PhysicsModule.dll`、`UnityEngine.AIModule.dll`、
   `UnityEngine.AnimationModule.dll`、`UnityEngine.AudioModule.dll`、
   `UnityEngine.UIModule.dll`、`UnityEngine.IMGUIModule.dll` 等；
   而永远内置的 `UnityEngine.CoreModule.dll` 在。
   `Unity.InputSystem.dll` 同样不在引用集里。
3. `Library/ScriptAssemblies/` 目前只剩 4 个文件（`Assembly-CSharp*`），
   所有包的 asmdef 一个都没编出来。
4. `Packages/packages-lock.json` 里有 18 个 `com.unity.modules.*` 条目，
   说明这些模块是本工程实际需要的，只是没有在 manifest 里被声明为直接依赖。

## 要做的事（只改一个文件）

编辑 `Packages/manifest.json`，在 `dependencies` 中补入下列 **18 个**内置模块包，
版本一律 `"1.0.0"`，与现有条目一起按字母序排列，保持 JSON 格式合法、缩进与现状一致：

```
com.unity.modules.ai
com.unity.modules.androidjni
com.unity.modules.animation
com.unity.modules.audio
com.unity.modules.director
com.unity.modules.hierarchycore
com.unity.modules.imageconversion
com.unity.modules.imgui
com.unity.modules.jsonserialize
com.unity.modules.particlesystem
com.unity.modules.physics
com.unity.modules.physics2d
com.unity.modules.physicscore2d
com.unity.modules.screencapture
com.unity.modules.terrain
com.unity.modules.ui
com.unity.modules.uielements
com.unity.modules.unitywebrequest
```

这 18 个不是我拍脑袋列的，是从本工程 `Packages/packages-lock.json` 里
逐个取出来的既有条目，不多不少。**不要增删这个清单。**

## 明确不要做的

- **不要改任何 `.cs` 文件**。特别是不要动
  `Assets/_Project/Scripts/Player/PlayerController.cs`、
  `Assets/_Project/Scripts/World/Door.cs`、
  `Assets/_Project/Scripts/World/PlayerInteractor.cs`——它们的代码是对的，
  报错是环境造成的，改代码只会把正确的代码改坏
- **不要改任何契约文件**
- **不要改 `Packages/packages-lock.json`**——Unity 会自己重新生成它
- **不要升级或降级任何现有包的版本**。工程锁定 Unity 6000.5.8f1，
  Input System 1.20.0 / URP 17.0.1 / Cinemachine 3.1.7 / AI Navigation 2.0.14
  都是刻意选定的，不要碰
- **不要删除 `Library/`**
- 只产出 `Packages/manifest.json` 一个文件的改动

## 需要新事件怎么办

本任务不涉及代码，不需要新事件。

## 验收标准

- `Packages/manifest.json` 是合法 JSON，`dependencies` 里同时包含
  原有的 11 个包和新增的 18 个 `com.unity.modules.*`
- Unity batchmode 编译**零错误**（这是本任务唯一真正的验收标准）
- `git diff` 只动了 `Packages/manifest.json` 一个文件
  （`Packages/packages-lock.json` 被 Unity 自动改写属于预期，不算违规）
