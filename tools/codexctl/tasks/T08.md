## 目标

把「找到了哪些证据」变成「**还剩哪几种鬼可能**」——这是 3×3 推理表真正发挥
作用的地方，也是 T13 判定笔记本的数据来源。

## 先读清楚：去重与计数已经有人做了

`GameManager` 已经维护 `HashSet<EvidenceType> _foundEvidence` 与
`public int FoundCount`。**不要重复实现证据收集与去重。**

本模块的职责只有一个：**根据已发现的证据推断候选鬼种**。

## 契约（已存在，不许改）

```
Assets/_Project/Scripts/Evidence/EvidenceType.cs
Assets/_Project/Scripts/Core/GameEvents.cs
Assets/_Project/Scripts/Ghost/GhostDefinition.cs
```

可用的：

```csharp
GameEvents.OnEvidenceFound(EvidenceType)   // 订阅：记录已发现
GameEvents.OnRoundStart                    // 订阅：重置
```

`EvidenceType`：`None=0` / `EMF5=1` / `UVFingerprint=2` / `GhostWriting=3`。

## 要做的文件

只产出 `Assets/_Project/Scripts/Evidence/EvidenceManager.cs`，
命名空间 `Residuum.Evidence`。

### 数据来源

`[SerializeField] private Residuum.Ghost.GhostDefinition[] _allGhosts;`

**这是本模块唯一允许的跨模块引用**，理由：`GhostDefinition` 是 ScriptableObject
纯数据资产，不是行为类，而推理必须知道每种鬼持有哪两项证据。
用 `definition.HasEvidence(EvidenceType)` 查询，**不要**引用 `GhostAI` 或
`Residuum.Ghost` 的任何其它类型。

### 推理逻辑

- 订阅 `OnEvidenceFound`，把证据记进 `HashSet<EvidenceType>`
  （本模块自己维护一份，用于推理；与 `GameManager` 那份互不干扰）
- `public IReadOnlyList<GhostDefinition> Candidates { get; }`
  —— 当前仍然可能的鬼种：**持有全部已发现证据**的那些
- `public int FoundCount { get; }`
- `public bool IsConclusive { get; }` —— 候选恰好剩 1 种
- 每次候选集合变化时触发
  `public UnityEngine.Events.UnityEvent onCandidatesChanged`
  —— 供 T13 笔记本 UI 在 Inspector 里连线刷新，**不要引用 UI**

### 排除法也要支持

3×3 推理表的一半价值在「确认某项证据**不存在**」也能推进推理。

- `public void MarkEvidenceRuled(EvidenceType type)` —— 玩家在笔记本上手动
  标记「这项确认没有」
- 被标记排除的证据，**持有它的鬼种从候选中剔除**
- `public void ClearRuled(EvidenceType type)` —— 撤销标记（玩家可能标错）
- 同一项证据不能既「已发现」又「已排除」：已发现的项调用 `MarkEvidenceRuled`
  时忽略并 `Debug.LogWarning` 一次

### 重置与校验

- 订阅 `OnRoundStart` 清空已发现与已排除，候选恢复为全部鬼种
- `Awake` 校验 `_allGhosts`：为空或长度为 0 时 `Debug.LogError` 并禁用自己；
  **额外校验每种鬼的 `evidences` 恰好 2 项且三种组合互不相同**，
  不满足时 `Debug.LogError` 指出是哪一个——这是推理表唯一性的保证，
  资产配错会让整个推理失效

## 验收标准

- 注入三个鬼资产后进 Play，`Candidates` 初始为 3 种
- 手动 `GameEvents.RaiseEvidenceFound(EvidenceType.EMF5)` 后候选剩
  怨灵与幽影（两种持有 EMF5 的鬼），`IsConclusive` 为 false
- 再 `RaiseEvidenceFound(EvidenceType.UVFingerprint)` 后候选**只剩怨灵**，
  `IsConclusive` 为 true
- 调 `MarkEvidenceRuled(EvidenceType.GhostWriting)` 后，持有鬼影书写的
  幽影与骚灵被剔除
- 对已发现的证据调 `MarkEvidenceRuled` 被忽略并只警告一次
- 每次候选变化触发一次 `onCandidatesChanged`
- `OnRoundStart` 后候选恢复为 3 种
- 故意把两个鬼资产的 `evidences` 配成相同组合，`Awake` 明确报错指出哪一个
- 除 UnityEngine / UnityEngine.Events / System 外只
  `using Residuum.Core;`，`GhostDefinition` 用全限定名引用
- 编译零错误
