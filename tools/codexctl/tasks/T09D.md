## 背景

`GhostAI.Start()` 在「当前鬼种 `leavesFootprints` 为 true 但 `_footprintPrefab`
为空」时打 `Debug.LogError`。

但灰盒阶段**根本没有脚印预制体**——美术要到 Day 6 才进场。一键装配工具按设计
不创建它，于是一按 Play 就是红字。

这与此前 `ItemSlotSystem` 那条「槽位有道具但未指定手持模型」是同一类问题：
**用红字报告一个正常状态**。实际后果已经发生过一次——Henry 被 Error Pause 挡在
Play 之外，误以为工程编译不过。红字在本工程里意味着有东西坏了，用它报告预期
状态会让真正的错误被淹没。

## 要改的文件

只改 `Assets/_Project/Scripts/Ghost/GhostAI.cs`，改动应当只有几行。

`Start()` 里这一处：

```csharp
if (Definition.leavesFootprints && _footprintPrefab == null)
{
    Debug.LogError($"[GhostAI:{name}] 当前鬼种需要脚印，但未注入脚印预制体。", this);
}
```

改为 `Debug.LogWarning`，文案要让人一眼看出**这是灰盒阶段的预期状态、不需要去修**，
并说明后果（该鬼种不会留下脚印，待美术资源到位后在 Inspector 里注入即可）。

**同时确认**：脚印生成的实际代码路径在 `_footprintPrefab` 为空时必须安全跳过，
不能空引用。如果当前实现已经有 null 保护就不用动；没有的话补上。

## 明确不要做的

- **不要**改 `GhostAI.cs` 里其它任何 `Debug.LogError`
  —— 缺 `NavMeshAgent`、缺 `Definition`、缺玩家引用那几条都是真错误，保持红字
- **不要**改状态机、导航、视线检测的任何逻辑
- **不要**创建脚印预制体，也不要改装配工具
- **不要**碰契约文件
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件的改动

## 验收标准

- 执行 `Residuum/搭建鬼装配` 后进 Play，关于脚印的那条是**黄色警告**而非红色错误
- 文案能让人看出这是灰盒阶段的预期状态，不需要处理
- 该鬼种在 Roam 状态下不会因为缺预制体而空引用报错
- `GhostAI.cs` 里其余 LogError 原样保留
- 编译零错误
