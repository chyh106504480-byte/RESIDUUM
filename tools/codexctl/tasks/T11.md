## 目标

一个可以钻进去的衣柜／床底。玩家瞄准它按 E 钻进去，猎杀中的鬼就找不到他了；
再按 E 出来。

**为什么现在必须做**：玩家冲刺 3.5 m/s，三种鬼的猎杀速度是 3.3 / 3.4 / 3.6，
而冲刺还有体力上限。骚灵一出，玩家跑不掉。没有躲藏点，每一次猎杀都是死亡，
结算永远是 F。

## 只做一个文件

`Assets/_Project/Scripts/World/HidingSpot.cs`，命名空间 `Residuum.World`，
实现 `Residuum.Core.IInteractable`。

## 好消息：另外两边都已经接好了，你只管发事件

**不要去改 `PlayerController` 或 `GhostAI`，一行都不要动。**它们已经写好了：

- `PlayerController.HandleHidingChanged`（`PlayerController.cs:673`）
  收到 `true` 后会清零移动输入、禁掉冲刺与下蹲、把视角夹在当前朝向附近
- `GhostAI` 在 `_isPlayerHiding` 为真时会跳过视线检测
  （`GhostAI.cs:925`）、跳过追击（`796`、`831`），只会按
  `_hidingCheckInterval` / `_hidingCheckChance` 偶尔过来转一圈

你要做的只有：把玩家挪到位、转好朝向、然后
`GameEvents.RaiseHidingChanged(true)`。

## 两个必须踩对的坑

### 一、顺序：先定位与转向，再发事件

`PlayerController.UpdateLook` **每帧无条件**写 `transform.rotation`。
而 `HandleHidingChanged(true)` 是在收到事件的那一刻读
`transform.eulerAngles.y` 当作受限视角的中心
（`PlayerController.cs:683`，那里的注释就是为这件事写的）。

所以顺序必须是：

```
1. 关掉 CharacterController
2. 写 transform.position
3. 写 transform.rotation
4. 打开 CharacterController
5. GameEvents.RaiseHidingChanged(true)     ← 必须最后
```

**倒过来就会被下一帧的 UpdateLook 覆盖掉**，玩家会站在柜子里朝着原来的方向。

### 二、CharacterController 会吃掉 transform.position 的写入

玩家身上挂的是 `CharacterController`，它启用时会覆盖直接写入的
`transform.position`。必须先 `enabled = false`、写完位置再 `enabled = true`。

用 `interactor.GetComponentInChildren<CharacterController>()` 拿（可能挂在
玩家根节点上，也可能在子节点）。**不要 using `Residuum.Player`，
`CharacterController` 是 UnityEngine 的类型，不涉及跨模块。**
取不到时 `Debug.LogWarning` 并放弃这次交互，不要抛异常。

## 要做的东西

```csharp
[Tooltip("玩家躲进来后所站的位置与朝向。一般放在柜子内部，朝向柜门")]
[SerializeField] private Transform _hidePoint;

[Tooltip("玩家出来后所站的位置与朝向。一般放在柜子正前方一步远")]
[SerializeField] private Transform _exitPoint;

[Tooltip("躲进去时的提示文本")]
[SerializeField] private string _enterPromptText = "[E] 躲进去";

[Tooltip("出来时的提示文本")]
[SerializeField] private string _exitPromptText = "[E] 出来";
```

`IInteractable` 三个成员：

- `PromptText` —— 已占用时返回 `_exitPromptText`，否则 `_enterPromptText`
- `CanInteract` —— `_hidePoint` 与 `_exitPoint` 都非空时为 true
- `Interact(GameObject interactor)` —— 没被占用就进去，已占用就出来

出来时按同样的五步顺序，位置用 `_exitPoint`，最后
`GameEvents.RaiseHidingChanged(false)`。

### 状态必须能被外部打断

订阅这三个事件，收到任何一个都要**强制把玩家弄出来**
（走完整的出去流程，包括发 `RaiseHidingChanged(false)`）：

- `GameEvents.OnRoundStart`
- `GameEvents.OnRoundEnd`
- `GameEvents.OnPlayerCaught`

`OnEnable` 订阅、`OnDisable` 取消订阅，两边都要写。
`OnDisable` 里若玩家还在里面，也要放出来——否则组件被禁用后
玩家会永远卡在不能动的状态。

### 场景里可能有多个柜子

每个 `HidingSpot` 各自管自己的占用状态。**不要写静态字段、不要写单例。**
玩家一次只可能在一个柜子里（他必须先出来才能瞄准另一个），
所以不需要全局互斥。

## Awake 校验

`_hidePoint` 或 `_exitPoint` 为空 → `Debug.LogError` 写清楚缺哪个，
并让 `CanInteract` 恒为 false。**不要 `enabled = false`**——
组件要保持启用才能收到上面三个打断事件。

- 不要做柜门开合动画

- 不要新建预制体或编辑器脚本
- 不要 using `Residuum.Player` 或 `Residuum.Ghost`

## 需要新事件怎么办

不要自己往 `GameEvents.cs` 里加。写在最终回复里说明签名与理由。

## 验收标准

Henry 会在场景里随便找个方块当柜子，挂上组件、拖两个空物体当
`_hidePoint` / `_exitPoint`，然后逐条点：

1. 编译通过，`git diff` 只有新增的 `HidingSpot.cs`（及其 meta）
2. 瞄准柜子，准星下方出现「[E] 躲进去」
3. 按 E，玩家瞬间移动到 `_hidePoint` 的位置**并且朝向 `_hidePoint` 的朝向**
   （这一条专门验上面那个顺序坑：如果朝向是原来的方向就是写反了）
4. 躲进去后 WASD 无法移动，鼠标只能小幅转动
5. 提示变成「[E] 出来」，按 E 后玩家出现在 `_exitPoint` 处、恢复移动
6. 按 P 强制猎杀，鬼追过来时躲进柜子：鬼失去目标，不再直冲玩家；
   偶尔会走到柜子附近转一圈然后离开
7. 躲在柜子里时按 F10 结束回合，玩家自动被放出来并恢复移动
8. 场景里放两个柜子，各自独立工作，进 A 出来后能进 B
9. 把 `_hidePoint` 清空，进 Play 时控制台报错点名这个字段，
   瞄准柜子没有提示、按 E 无反应、不抛空引用
