## 症状（核心玩法失效）

猎杀一开始，**鬼立刻朝玩家的精确位置直线赶来**，哪怕中间隔着几堵墙、
隔着一整层楼。它会一路走到最近的墙边卡住，因为它知道你在墙那边。

「切断视线甩掉鬼」这个核心逃生手段因此完全失效——鬼从来不需要看见你。

## 根因

`GhostAI` 猎杀开始的初始化里（约 `GhostAI.cs:821`）：

```csharp
if (_player != null)
{
    _lastKnownPlayerPosition = _player.position;
    _hasLastKnownPlayerPosition = true;
}
```

**无条件**把玩家的真实坐标写进「最后已知位置」，不管当时看不看得见。

视线遮挡本身是好的（`Physics.Linecast` 工作正常，Gizmo 红线正确表示
被挡住），问题是鬼在开局就白拿了一次答案。

## 只改一个文件

`Assets/_Project/Scripts/Ghost/GhostAI.cs`

## 改法

猎杀开始时，**先做一次真实的视线判定**，看得见才记录位置：

```csharp
if (_player != null && EvaluatePlayerLineOfSight())
{
    _lastKnownPlayerPosition = _player.position;
    _hasLastKnownPlayerPosition = true;
    _hasLineOfSight = true;
    _lastSeenTime = Time.time;
}
else
{
    _hasLastKnownPlayerPosition = false;
    _hasLineOfSight = false;
}
```

注意这几行在现有初始化里的位置：`_hasLineOfSight = false;` 与
`_lastSeenTime = Time.time;` 已经在上面几行设过，
**改完不要留下自相矛盾的重复赋值**，整理成一处。

`EvaluatePlayerLineOfSight()` 是文件里已有的方法，直接调用即可。

## 没有目标时鬼该干什么

`_hasLastKnownPlayerPosition` 为 false 时，猎杀中的鬼**不能站着不动**。
让它走现有的「猎杀搜索」路径：在自己周围
`_huntSearchRadius` 范围内随机取点巡视，直到看见玩家为止。

文件里已经有 `_huntSearchTargetActive` / `_huntSearchRadius` 这套逻辑，
**复用它，不要新写一套**。看一下 `UpdateHunt` 里没有已知位置时走的分支，
确保它会进入搜索而不是空转。

## 一并确认，但只在确实有问题时才改

`UpdateHunt` 里如果还有别处**无条件**读 `_player.position` 来设目标点，
一并改成只在 `_hasLineOfSight` 为真时才更新。

`_checkingHidingSpot` 那一路（约 966 行）是**例外，不要动**——
那是玩家躲藏时鬼按概率过来转一圈的既有设计。

## 明确不要做的

- 不要改视线检测本身（`EvaluatePlayerLineOfSight`、`EvaluateSightRay`、
  `_sightBlockMask` 的用法）——它们是对的
- 不要改 Gizmo 绘制
- 不要改 `HuntController`、`PlayerController`、`LightManager`
- 不要往 `GameEvents.cs` 加任何东西
- 不要改猎杀速度、时长、冷却
- 不要新建文件

## 验收标准

1. 编译通过，`git diff` 只有 `GhostAI.cs` 一个文件
2. 玩家躲在鬼看不见的房间（隔一堵墙或在楼下），按 P 强制猎杀：
   **鬼不会直奔玩家**，而是在自己附近搜索
3. 玩家走进鬼的视野：鬼立刻发现并直冲过来（Gizmo 线变绿）
4. 玩家再躲回墙后：鬼冲到最后消失点，在附近搜索一阵，
   而不是穿过墙继续跟
5. 玩家在鬼的视野内时按 P：鬼立刻锁定并追击，不会先傻站着搜索
6. 猎杀期间鬼**任何时候都不会站着不动**——要么追、要么搜
7. 猎杀结束后鬼正常回到巡逻
