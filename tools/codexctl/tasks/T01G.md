## 背景

`PlayerController` 已经写完并过审，但**场景里从来没有玩家**。
`Assets/Scenes/SampleScene.unity` 至今还是 Unity 建工程时的默认模板场景，
只有 `Main Camera`、`Directional Light`、`Global Volume`，工程里也没有任何预制体。
所以进播放模式什么都不会发生 —— 脚本没有任何实例在运行。

本任务做一个**编辑器菜单命令**，一键把玩家装配搭进当前打开的场景，
把所有序列化引用正确连好，让 T01F 的光标锁定和视角控制能被实际测试。

## 目标

新增一个编辑器工具脚本，点一次菜单就得到一个可直接进播放模式的玩家。

## 要做的文件

只做这一个文件：

**`Assets/_Project/Scripts/Player/Editor/PlayerRigBuilder.cs`**

### 命名空间（关键，先读这条）

命名空间必须是 `Residuum.Player.Editor`。

这样它能直接看到 `Residuum.Player.PlayerController`，**不需要也不允许写
`using Residuum.Player;`** —— C# 会自动向上层命名空间解析类型。
架构铁律禁止 `using Residuum.<非 Core>`，写了会被闸门判为 error。

文件放在名为 `Editor` 的文件夹下，Unity 会自动把它编进
`Assembly-CSharp-Editor`，不会进最终构建。**不要新建 asmdef 文件。**

### 菜单命令

`[MenuItem("Residuum/搭建玩家装配")]`，静态方法。

只在人点菜单时执行，**绝对不要**用 `[InitializeOnLoad]` 之类在打开工程时自动跑。

### 它要做的事

1. **幂等检查**：先在当前场景找有没有已存在的 `PlayerController`
   （用 `Object.FindFirstObjectByType<PlayerController>()`，
   **禁止** `FindObjectOfType`，Unity 6 已弃用）。
   已存在就不要再建第二个 —— 选中它、打印一条提示、直接返回。

2. **地面**：当前场景没有地板，`CharacterController` 会带着 -20 的重力永远下坠。
   若场景中没有任何地面碰撞体，创建一个 `Plane`（缩放 2,1,2 左右）命名 `Ground`，
   放在原点。已经有地面就不要重复建。

3. **玩家物体**：新建 `GameObject` 命名 `Player`，放在地面上方（例如 y = 0.1）。
   - 加 `CharacterController`，参数**必须和 `PlayerController` 的默认值对齐**，
     否则站立/蹲伏高度会打架：
     - `height` = `1.8`（对应 `_standingHeight`）
     - `center` = `(0, 0.9, 0)`（对应 `_standingCenter`）
     - `radius` = `0.3`
   - 加 `PlayerController` 组件。

4. **相机枢轴**：在 `Player` 下建子物体命名 `CameraPivot`，
   `localPosition` = `(0, 1.6, 0)`（眼高，低于胶囊顶部 1.8），`localRotation` 为单位旋转。

5. **相机**：复用场景里**已有的 `Main Camera`**，把它挂到 `CameraPivot` 下，
   `localPosition` 归零、`localRotation` 归零。
   **不要新建相机** —— 会多出第二个 `AudioListener` 并触发警告。
   万一场景里确实找不到相机，才新建一个并打上 `MainCamera` tag。

6. **连引用（关键，最容易做错的一步）**：
   `_inputActions` 和 `_cameraPivot` 都是 `private [SerializeField]` 字段，
   **不能**直接赋值，也**不要**用反射。必须走
   `SerializedObject` / `FindProperty` / `ApplyModifiedProperties`：
   - `_inputActions` ← `AssetDatabase.LoadAssetAtPath<InputActionAsset>("Assets/InputSystem_Actions.inputactions")`
     （这是工程现有资产，**不要新建 Input Action Asset**）
   - `_cameraPivot` ← 上面那个 `CameraPivot` 的 `Transform`

   字段名就是 `_inputActions` 和 `_cameraPivot`，照抄，不要猜别的名字。
   若资产加载不到，打错误日志并中止，不要留下半成品装配。

7. **可撤销 + 存盘标记**：
   - 所有新建物体用 `Undo.RegisterCreatedObjectUndo`，改父子关系用 `Undo.SetTransformParent`，
     加组件用 `Undo.AddComponent`，让使用者能 Ctrl+Z 一次性撤销。
   - 结束时 `EditorSceneManager.MarkSceneDirty(...)`，否则改动不会提示保存。
   - **不要**自动保存场景，把存不存交给使用者决定。

8. 结束时选中 `Player`（`Selection.activeGameObject`）并打一条成功日志。

## 明确不要做的

- 不要碰 `PlayerController.cs` 或任何其它已有脚本，本任务只加一个新文件。
- 不要新建 asmdef、不要新建 Input Action Asset、不要引入任何新包。
- 不要做预制体化 / 存 prefab —— 那是后面的事，本任务只管当前场景。
- 不要顺手加暂停菜单、准星 UI、脚步音效、玩家层设置。
- 不要写运行时代码，这个文件只在编辑器下存在。

## 需要新事件怎么办

本任务不该需要任何新事件。如果你认为需要，**不要自己加进契约文件**，
写在最终回复里说明。

## 验收标准

- 菜单 `Residuum/搭建玩家装配` 存在，点击后场景里出现
  `Player`（含 `CharacterController` + `PlayerController`）、
  其下 `CameraPivot`、再其下 `Main Camera`。
- 在 Inspector 上能看到 `PlayerController` 的 `Input Actions` 和 `Camera Pivot`
  两个槽位**都已填好**，不是 `None`。
- 进播放模式后：鼠标被锁在屏幕中央且不可见，移动鼠标视角跟着转、不卡窗口边缘；
  WASD 能走动，人不下坠穿地。
- 退出播放模式后编辑器鼠标恢复正常。
- 再点一次菜单不会建出第二个玩家。
- 点完菜单按一次 Ctrl+Z 能撤销干净。
- 文件命名空间为 `Residuum.Player.Editor`，全文件没有 `using Residuum.` 开头的语句。
- 编译零错误。
