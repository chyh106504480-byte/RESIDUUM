## 背景

`ItemSlotSystem.PrepareHeldModels()` 在「槽位有道具但 `_heldModels` 对应项为空」
时打 `Debug.LogError`。但这在当前阶段是**完全正确的配置**：灰盒阶段还没有任何
手持模型网格，美术要到 Day 6 才进场。一键测试台按设计把 `_heldModels` 留空，
于是每次进 Play 都会看到一行红字，而实际什么都没坏——那个分支后面就是
`continue`，槽位功能完全正常。

红字在本工程里意味着有东西坏了。用它来报告一个正常状态，会让真正的错误被淹没。

## 要改的文件

只改 `Assets/_Project/Scripts/Items/ItemSlotSystem.cs`，改动应当只有几行。

`PrepareHeldModels()` 里这一处：

```csharp
if (_holdables[index] != null)
{
    Debug.LogError($"ItemSlotSystem 第 {index + 1} 槽已有道具，但未指定手持模型。", this);
}
```

改为 `Debug.LogWarning`，并把文案改成能说明「这是预期状态」的措辞，例如指出
灰盒阶段尚无手持模型、待美术资源到位后再填。具体措辞你定，要求是让人看一眼
就知道**不需要去修**。

## 明确不要做的

- **不要**改同一方法里其它两处 `Debug.LogError`
  （「Hand Anchor 自身作为手持模型」和 `CacheSlots` 里「组件未实现 IHoldable」），
  那两个是真错误，保持红字
- **不要**改 `PrepareHeldModels` 的控制流，`continue` 保持不变
- **不要**改 `TestBenchBuilder.cs`，更不要去造占位模型物体
- **不要**碰契约文件
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件的改动

## 验收标准

- 执行 `Residuum/搭建测试台` 后进 Play，Console 里那条关于手持模型的消息是
  **黄色警告**而不是红色错误
- 文案能让人看出这是灰盒阶段的预期状态，不需要处理
- 另外两处 `Debug.LogError` 原样保留
- 编译零错误
