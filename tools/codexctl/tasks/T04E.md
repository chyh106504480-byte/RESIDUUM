## 背景

手工建 `RoomVolume` 很慢：每间房要新建空物体、加 `BoxCollider`、勾 `Is Trigger`、
肉眼调 Size 罩住房间、加组件、填中文名。九个房间要重复九遍，还容易把盒子调得
伸出墙外——那会让鬼的落脚点被扔进隔壁房间。

做成菜单：**选中房间的地板（或房间的整组物体），一键生成尺寸贴合的 RoomVolume。**
与 `搭建玩家装配`、`搭建测试台`、`搭建鬼装配`、`搭建回合装配` 同一性质。

## 要做的文件

只产出 `Assets/_Project/Scripts/World/Editor/RoomVolumeBuilder.cs`，
命名空间 `Residuum.World.Editor`。

**先读 `Assets/_Project/Scripts/World/Editor/TestBenchBuilder.cs`**，写法保持一致：
`Undo` 分组、`SerializedObject` 注入、`FindProperty` 为 null 时抛
`InvalidOperationException` 带中文说明、失败 `Undo.RevertAllDownToGroup` 整体回滚、
结束 `MarkSceneDirty`。

### 菜单一：`Residuum/为选中对象创建 RoomVolume`

**输入**：Hierarchy 里当前选中的一个或多个物体（通常是某个房间的地板，
或该房间的整组子物体）。没有选中任何场景物体时 `Debug.LogError` 提示并返回。

**做什么**：

1. 计算选中物体（含其所有子物体）的 `Renderer.bounds` 并集；
   没有 `Renderer` 时回退用 `Collider.bounds`；两者都没有则报错返回
2. 在 Hierarchy 根部新建空物体，命名 `BLK_Room_<第一个选中物体的名字>`
3. 位置放在包围盒中心，但 **Y 坐标改为包围盒底面 + 房间高度的一半**
   （这样盒子底面正好压在地板上）
4. 加 `BoxCollider`，**`isTrigger = true`**，尺寸：
   - X / Z = 包围盒尺寸**减去内缩量**（`[SerializeField]` 不可用，这是编辑器工具，
     用 `private const float` 即可，默认内缩 `0.3` 米）
   - Y = 房间高度常量，默认 `2.5`
   - **内缩是为了不伸出墙外**：`GetRandomPointInside` 在盒子 XZ 平面随机取点，
     伸出去会让鬼被扔进隔壁房间
   - 内缩后任一边小于 `0.5` 米时，改用原尺寸并 `Debug.LogWarning` 说明该房间太小
5. 加 `Residuum.World.RoomVolume`，用 `SerializedObject` 注入
   （字段名已核对，照抄）：
   - `_roomName` ← 第一个选中物体的名字
   - `_roomId` ← 同上（人之后可改）
   - `_canBeGhostRoom` ← **`false`**（默认不当鬼房，由人挑几间勾上，
     避免一键生成后所有房间都是候选）
6. 生成后选中新建的物体，方便立刻改名或调整

**多选时的行为**：如果选中了多个**互不相关**的物体，仍然只生成**一个**罩住全部的
盒子——因为用户的意图通常是「这几个物体属于同一个房间」。
在 `Debug.Log` 里说明合并了几个物体。

### 菜单二：`Residuum/检查 RoomVolume 重叠`

扫描场景里所有 `RoomVolume`，两两检测 `BoxCollider.bounds` 是否相交，
把相交的组合列进一条 `Debug.LogWarning`（房间名 + 重叠体积）。
没有重叠时 `Debug.Log` 报「未发现重叠」。

**为什么需要**：重叠区域里 `CurrentPlayerRoom` 判定会飘。这个检查让人一眼看出
哪两间需要调小。

### 菜单三：`Residuum/创建 RoomManager`

场景里没有 `RoomManager` 时，在根部新建空物体 `RoomManager` 并挂上组件；
已存在则 `Debug.Log` 说明并选中它，不重复创建。

查找用 `FindAnyObjectByType<T>(FindObjectsInactive.Include)`。
**不要用 `FindObjectOfType` 或 `FindFirstObjectByType`，两者在 Unity 6 都已弃用。**

## 关于跨模块引用

本文件在 `Scripts/World/Editor/` 下，引用 `Residuum.World` 的类型属于同模块，
不涉及跨模块问题。

## 明确不要做的

- **不要**改任何运行时脚本，包括 `RoomVolume.cs` 与 `RoomManager.cs`
- **不要**自动判断哪几间该当鬼房 —— 那是关卡设计决策，一律生成为 false
- **不要**自动烘焙 NavMesh
- **不要**自动保存场景
- **不要**尝试从 NavMesh 或几何体自动「识别房间」—— 只处理用户明确选中的物体
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件

## 验收标准

- 选中一个房间的地板物体，执行 `Residuum/为选中对象创建 RoomVolume`，
  生成的盒子在 Scene 视图里贴合该房间且**不穿墙**，底面压在地板上
- 生成的 `RoomVolume` 中文名等于选中物体名，`_canBeGhostRoom` 为 false
- 多选几个物体时生成一个罩住全部的盒子，并在 Console 说明合并了几个
- 没有选中任何物体时报明确中文错误，不创建任何东西
- 选中没有 Renderer 也没有 Collider 的空物体时报错返回，不崩
- `Residuum/检查 RoomVolume 重叠` 能列出相交的房间组合；无重叠时明确报「未发现重叠」
- `Residuum/创建 RoomManager` 幂等，已存在时不重复创建
- 每次生成都能用一次 Ctrl+Z 撤销
- 编译零错误
