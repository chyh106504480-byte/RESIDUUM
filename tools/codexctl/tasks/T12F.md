## 背景

T12 已通过终审，闸门与编译都过。两条必修，其中第一条是你自己在最终回复里
诚实指出的——判断正确，这次去修它。

只改 `Assets/_Project/Scripts/Player/PlayerSanity.cs`。

## 必修一：光照检测不能依赖 Collider

`Physics.OverlapSphereNonAlloc` 返回的是 **Collider**，而场景灯光**通常只有
`Light` 组件、没有碰撞体**——本工程用的公寓资产包里近百盏灯全都如此。
结果是「附近有启用的灯」永远判定为 false，理智永远按黑暗速率 0.12/秒 衰减，
有灯房间 0.06/秒 的设定完全失效。

**改为直接按 `Light` 组件判定：**

- 在 `Start`（或首次检测时）用
  `FindObjectsByType<Light>(FindObjectsInactive.Exclude, FindObjectsSortMode.None)`
  —— **等一下，不要用带 SortMode 的重载，那个在 Unity 6 已弃用。**
  正确写法是 `FindObjectsByType<Light>(FindObjectsInactive.Exclude)`。
  把结果缓存到字段，**不要每次检测都重新查找**
- 每次检测遍历缓存，满足以下全部条件即算「有光」：
  - `light != null && light.isActiveAndEnabled`
  - 到玩家的距离 ≤ `light.range`（点光源与聚光灯）；
    `LightType.Directional` 视为始终照亮，直接算有光
  - **不属于玩家自身或其子层级** —— 保留你上一轮加的这条排除逻辑，
    否则手电筒会被当成房间灯光造成双重减免
- 提供 `[SerializeField]` 的缓存刷新间隔（默认 `5` 秒），
  期间新增/销毁的灯光通过定期刷新纳入，不必每帧重查
- 保留 `_useLightProbe` 开关与 `SetInLitRoom(bool)` 简单方式，行为不变

原来的 `_lightDetectionLayers`、`_lightOverlapBufferSize` 与相关缓冲字段
若不再需要，一并删除，不要留死代码。

## 必修二：阈值步长改为可调

`SanityThresholdStep = 25f` 是平衡参数——它决定音频与后处理分几级加强，
属于手感范畴。改为 `[SerializeField] private float _sanityThresholdStep = 25f;`
带中文 `[Tooltip]`，并做非法值保护（≤ 0 时按 25 处理并告警一次）。

**`MinimumSanity = 0` 与 `MaximumSanity = 100` 保持常量** —— 那是理智的定义域，
不是可调数值。

## 明确不要做的

- **不要**改衰减速率、扣减值、安全区恢复等既有 `[SerializeField]` 的默认值
- **不要**改事件广播逻辑与阈值触发规则
- **不要**改安全区、鬼事件、猎杀期额外衰减的任何逻辑
- **不要**碰契约文件或其它任何文件
- **不要**用 `FindObjectsByType` 的 `FindObjectsSortMode` 重载（Unity 6 已弃用）
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件的改动

## 验收标准

- 场景里放一盏**没有任何 Collider 的点光源**，玩家走进其 `range` 内，
  理智衰减从 0.12/秒 降到 0.06/秒
- 走出 `range` 后恢复 0.12/秒
- 玩家自己的手电筒**不会**被算作房间灯光
- 阈值步长可在 Inspector 调整，改成 20 后跌破 80/60/40/20 各触发一次
- 步长填 0 或负数时按 25 处理并告警一次，不刷屏
- 除 UnityEngine / System 外只 `using Residuum.Core;`
- 编译零错误
