## 背景

T09 `GhostAI` 的代码已通过终审，但**行为一次都没验证过**，因为两样东西不存在：

1. **三种鬼的 `.asset` 资产**。契约里只有 `GhostDefinition` 类，没有怨灵 / 幽影 /
   骚灵的实例。`GhostAI.Definition` 为 null 时会 `LogError` 并禁用自己——鬼根本不动。
2. **场景里的鬼装配**。挂 `NavMeshAgent` + `GhostAI`、注入定义资产、玩家引用、
   巡逻点、鬼房中心，全是手工连线。

做成菜单，和 `Residuum/搭建玩家装配`、`Residuum/搭建测试台` 同一性质。

## 背景补充：上一轮你正确地停手了

你上一轮发现 `GhostAI.Definition` 是非序列化的自动属性，无法用 `SerializedObject`
持久注入，而任务又禁止改 `GhostAI.cs`——两个要求互相矛盾，于是你没产出任何文件
并说明了原因。**判断完全正确，错在任务包。**本轮明确授权你改 `GhostAI.cs`。

## 要做的文件（两个）

### 文件一：`Assets/_Project/Scripts/Ghost/GhostAI.cs`（小改）

把

```csharp
public GhostDefinition Definition { get; set; }
```

改为「序列化后备字段 + 属性」的形式：

- 新增 `[SerializeField] private GhostDefinition _definition;`，带中文 `[Tooltip]`
  说明「本回合鬼种定义；可在 Inspector 预先指定用于单独测试，正式回合由
  GameManager 在开始时注入并覆盖」
- `Definition` 属性的 getter 返回 `_definition`，setter 写入 `_definition`
- **其余逻辑一律不动**：`Awake` 里对 null 的检查、报错、禁用自己的行为保持原样

这样编辑器工具能预先指定一个鬼种做单机测试，而 T15 `GameManager` 依然可以在
回合开始时通过属性覆盖。**改动应当只有几行。**

### 文件二：`Assets/_Project/Scripts/Ghost/Editor/GhostSetupBuilder.cs`

命名空间 `Residuum.Ghost.Editor`。

**先读 `Assets/_Project/Scripts/World/Editor/TestBenchBuilder.cs`**，写法与它保持一致：
`Undo` 分组、`SerializedObject` 注入、`FindProperty` 为 null 时抛
`InvalidOperationException` 带中文说明、失败 `Undo.RevertAllDownToGroup` 整体回滚、
结束 `MarkSceneDirty`。

### 菜单一：`Residuum/创建三种鬼资产`

在 `Assets/_Project/ScriptableObjects/Ghosts/` 下创建三个 `GhostDefinition` 资产
（目录不存在则创建）。**已存在同名资产时不覆盖**，`Debug.Log` 说明并跳过。

**字段值照下表填，这些数字来自 GDD，不要自己改动：**

| 字段 | GhostDef_Spirit | GhostDef_Wraith | GhostDef_Poltergeist |
|---|---|---|---|
| `ghostName` | `怨灵` | `幽影` | `骚灵` |
| `displayNameEN` | `Spirit` | `Wraith` | `Poltergeist` |
| `evidences` | `EMF5`, `UVFingerprint` | `EMF5`, `GhostWriting` | `UVFingerprint`, `GhostWriting` |
| `walkSpeed` | `1.6` | `1.7` | `1.7` |
| `huntSpeed` | `1.6` | `1.7` | `1.8` |
| `leavesFootprints` | `true` | **`false`** | `true` |
| `huntDuration` | **`30`** | `25` | `22` |
| `huntCooldown` | `25` | `25` | `25` |
| `sanityDrainMultiplier` | `1.0` | `1.0` | **`1.5`** |
| `canSprintBurst` | `false` | **`true`** | `false` |
| `sprintBurstInterval` | `6` | `6` | `6` |
| `massThrowOnHunt` | `false` | `false` | **`true`** |
| `interactFrequency` | `1.0` | `1.0` | **`2.0`** |

`journalDescription` 各写一句中文性格描述，照 GDD：
怨灵「迟缓、执拗，长时间停留在鬼房，脚步声沉重清晰」；
幽影「飘忽无踪，不在地板留下脚印」；
骚灵「暴躁、破坏，频繁抛掷物品制造巨响」。

**加粗的那几个值是三种鬼的人格所在**，填错了三种鬼就没区别了。
`evidences` 数组长度必须恰好 2，且三种组合互不相同——这是 3×3 推理表的唯一性保证。

创建后 `AssetDatabase.SaveAssets()` 并 `Debug.Log` 列出创建了哪几个。

### 菜单二：`Residuum/搭建鬼装配`

在场景里生成 `Ghost` 物体：

- 挂 `UnityEngine.AI.NavMeshAgent`：`radius = 0.3`、`height = 2`、
  `speed` 留默认（`GhostAI` 会按 definition 覆盖）、`stoppingDistance = 0.5`
- 挂 `Residuum.Ghost.GhostAI`
- 建一个子物体 `Body`，挂 `MeshRenderer` + `MeshFilter`（用 Capsule 网格），
  作为占位可见体，并用 `SerializedObject` 注入到 `GhostAI` 的渲染器数组字段
- 用 `SerializedObject` 注入：
  - `GhostDefinition` —— 用 `AssetDatabase` 找 `GhostDef_Spirit`，找不到就报错提示先执行菜单一
  - 玩家 `Transform` —— 从场景里的 `Residuum.Player.PlayerController` 取其 transform，
    找不到就 `Debug.LogError` 提示先执行 `Residuum/搭建玩家装配`
- **巡逻点**：在 `Ghost` 下建一个空物体 `RoamPoints`，其下建 4 个空子物体
  `RoamPoint_1`–`RoamPoint_4`，**全部放在原点**（位置由人手动摆到各房间），
  并把这 4 个 Transform 注入 `GhostAI` 的巡逻点数组
- **鬼房中心与半径**：注入 `Ghost` 自身位置作为中心、半径填 `4`，
  并 `Debug.LogWarning` 提示这是占位值、正式回合由 T15 GameManager 注入

**字段名一律先读 `GhostAI.cs` 确认**，不要凭猜写 `FindProperty` 的字符串；
找不到就抛异常，不要静默跳过。

幂等：场景已有 `GhostAI` 时不重复创建，`Debug.Log` 说明并选中它。

## 关于跨模块引用

本文件在 `Scripts/Ghost/Editor/` 下，会引用 `Residuum.Player.PlayerController`
的类型。**编辑器装配工具允许这样做**，理由与 T01H / T01I 相同。
沿用它们的做法，**用全限定名而不是 using**，只借类型不给命名空间开门。

## 明确不要做的

- **不要**改 `GhostAI.cs` 里除 `Definition` 属性之外的任何逻辑
- **不要**改其它运行时脚本
- **不要**碰契约文件（`GhostDefinition.cs` 只读不写）
- **不要**自动摆放巡逻点到具体房间 —— 那是人的设计决策，你只建空物体
- **不要**创建 NavMeshSurface 或烘焙导航网格
- **不要**自动保存场景
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出上面两个文件

## 验收标准

- 执行 `Residuum/创建三种鬼资产`，`Assets/_Project/ScriptableObjects/Ghosts/`
  下出现三个资产，Inspector 里数值与上表逐项一致
- 三个资产的 `evidences` 各恰好 2 项且组合互不相同，`OnValidate` 不报警告
- 再次执行菜单不覆盖已有资产
- 在已有玩家装配的场景执行 `Residuum/搭建鬼装配`，出现 `Ghost` 物体，
  带 `NavMeshAgent` 与 `GhostAI`，定义资产与玩家引用均已注入，
  其下有 `RoamPoints` 与 4 个空巡逻点
- 进 Play 不报 LogError、`GhostAI` 不自禁用
- 没有 `PlayerController` 的场景执行菜单，报明确中文错误且不创建任何东西
- 一次 Ctrl+Z 能撤销整个鬼装配
- `GhostAI` 的 `Definition` 可在 Inspector 里指定，且 `GameManager` 仍能在运行时通过属性覆盖
- 编译零错误
