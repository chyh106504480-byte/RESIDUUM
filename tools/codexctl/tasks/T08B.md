## 目标

给已经存在的 `EvidenceManager` 补三个**只读查询接口**。这是纯增量改动，
不允许改动任何现有行为。

## 为什么需要

T13 判定笔记本要画的是三行证据勾选框，每行有三态：

| 状态 | 界面表现 | 数据来源 |
|---|---|---|
| 已发现 | 打勾、锁死不可点 | 现在没有接口 |
| 已排除 | 打叉 | 现在没有接口 |
| 未知 | 空白、可点 | 上面两个都是 false |

现在 `EvidenceManager` 只公开 `Candidates` / `FoundCount` / `IsConclusive`，
笔记本拿不到单项证据的状态。如果让笔记本自己另存一份状态，会和
`EvidenceManager` 内部的状态漂移——特别是 `HandleEvidenceFound` 里
「实际发现的证据会自动撤销此前的手动排除」这一条，笔记本那份不会跟着变，
于是界面显示打叉、实际推理按已发现算，两边对不上。

## 要做的文件

**只改这一个文件**：`Assets/_Project/Scripts/Evidence/EvidenceManager.cs`

加三个成员：

```csharp
/// <summary>该项证据是否已被实际采集到。</summary>
public bool IsFound(EvidenceType type)

/// <summary>该项证据是否被玩家手动标记为「确认不存在」。
/// 已发现的证据永远返回 false。</summary>
public bool IsRuled(EvidenceType type)

/// <summary>候选鬼种为空——玩家的手动排除与实际发现互相矛盾。
/// 界面应提示玩家撤销某项排除。</summary>
public bool HasContradiction { get; }
```

`IsFound` / `IsRuled` 对无效类型（`EvidenceType.None` 或未定义值）
直接返回 `false`，**不要打警告日志**——界面每帧都可能查询，会刷屏。
文件里已有的 `IsValidEvidence` 私有方法可以直接用。

## 顺带修一个空引用

`RebuildCandidates()` 第一行读 `_allGhosts.Length`。当 `Awake` 的校验失败时
组件会被 `enabled = false`，但 `MarkEvidenceRuled` / `ClearRuled` 是公开方法，
笔记本的按钮仍然能通过 UnityEvent 调到它们，此时 `_allGhosts` 可能为 null
→ 每次点击抛一次 NullReferenceException。

在 `RebuildCandidates()` 开头加一条守卫：`_allGhosts` 为 null 时直接 return。
**不要**改 `Awake` 的校验逻辑，也不要改 `enabled = false` 那条。

## 明确不要做的

- 不要改 `MatchesCurrentEvidence`、`ValidateGhostDefinitions`、
  `HandleEvidenceFound`、`HandleRoundStart` 的任何现有逻辑
- 不要改 `Candidates` / `FoundCount` / `IsConclusive` 的语义
- 不要加新的 `[SerializeField]` 字段
- 不要碰 `onCandidatesChanged` 的触发时机
- 不要动 `Assets/_Project/Scripts/` 下的其它任何文件
- 不要新建文件

## 需要新事件怎么办

不要自己往 `GameEvents` 里加。写在最终回复里说明需要什么签名。
本任务预期不需要新事件。

## 验收标准

1. 编译通过，`EvidenceManager` 之外没有任何文件被改动
2. 进 Play，三项证据的 `IsFound` 与 `IsRuled` 初始全为 `false`，
   `HasContradiction` 为 `false`
3. 调用 `MarkEvidenceRuled(EvidenceType.EMF5)` 后
   `IsRuled(EMF5)` 为 `true`、`IsFound(EMF5)` 为 `false`
4. 随后触发 `GameEvents.RaiseEvidenceFound(EvidenceType.EMF5)`，
   `IsFound(EMF5)` 变 `true` 且 `IsRuled(EMF5)` 变回 `false`
   （对应「发现优先于手动排除」那条既有逻辑）
5. 手动排除某只鬼持有的全部两项证据、同时又发现了其中一项时，
   候选不会归零；构造真正矛盾的输入时 `HasContradiction` 为 `true`
6. `IsFound(EvidenceType.None)` 返回 `false` 且控制台无任何日志输出
