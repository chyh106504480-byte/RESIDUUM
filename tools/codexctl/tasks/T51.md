## 目标

游戏中按 `ESC` 弹出一个小菜单，两个按钮：

```
继续游戏      关掉菜单回到游戏
返回主菜单    重载场景，回到主菜单
```

这是 demo，**不做设置、音量、存档**，就这两个。

## 要做两个文件

1. `Assets/_Project/Scripts/UI/PauseMenuUI.cs`（新建）
2. `Assets/_Project/Scripts/UI/Editor/UISetupBuilder.cs`（加一段搭建）

## 文件一：`PauseMenuUI.cs`，命名空间 `Residuum.UI`

```csharp
[SerializeField] private GameObject _panelRoot;
[SerializeField] private UnityEngine.UI.Button _resumeButton;
[SerializeField] private UnityEngine.UI.Button _quitToMenuButton;

[Tooltip("呼出/关闭菜单的按键")]
[SerializeField] private UnityEngine.InputSystem.Key _toggleKey
    = UnityEngine.InputSystem.Key.Escape;

[Tooltip("拖入玩家身上的 PlayerController。菜单打开时禁用它")]
[SerializeField] private MonoBehaviour _playerControllerBehaviour;

[Tooltip("可选：返回主菜单前做一次渐暗过场")]
[SerializeField] private ScreenFader _screenFader;
```

### 开关

按键检测用 `UnityEngine.InputSystem.Keyboard.current`，
参照 `JournalUI.Update` 的写法（`wasPressedThisFrame`，
对 `Keyboard.current == null` 做保护）。

打开时禁用 `_playerControllerBehaviour`、关闭时恢复——
和结算界面同一套，**不要自己写 `Cursor.lockState` / `Cursor.visible`**。

`_playerControllerBehaviour` 为 null 时跳过，不报错。

### 「继续游戏」

隐藏面板、恢复 PlayerController。

### 「返回主菜单」

重载当前场景：

```csharp
var scene = UnityEngine.SceneManagement.SceneManager.GetActiveScene();
UnityEngine.SceneManagement.SceneManager.LoadScene(scene.name);
```

**重载前必须先恢复 `_playerControllerBehaviour`**——不恢复的话
新场景里光标状态可能是错的。

`_screenFader` 不为空时，把重载放进 `FadeThrough` 的回调里，
先渐暗再重载；为空就直接重载。

**场景不在 Build Settings 里时 `LoadScene` 会失败**。
调用前用 `Application.CanStreamedLevelBeLoaded(scene.name)` 判断，
为 false 时 `Debug.LogError` 明确写出
「场景 X 不在 Build Settings 中，无法返回主菜单，请到
File > Build Profiles 把它加进去」，然后返回，**不要抛异常**。

### 什么时候不能开

- 主菜单还显示着的时候不该能按 ESC。判据：订阅
  `GameEvents.OnRoundStart` / `OnRoundEnd`，只在回合进行中才响应
  `ESC`。初始状态为「回合未开始」
- 回合结束（结算界面弹出）后也不响应

### 其它

- `_panelRoot` 不允许是本组件所在的 GameObject 或它的祖先，
  `Awake` 检出要报错并禁用组件。参照 `ResultScreenUI` 的同类校验
- `Awake` 时隐藏面板
- `OnDisable` 里若面板还开着要隐藏并恢复 PlayerController
- 不要碰 `Time.timeScale`

## 文件二：搭建工具加一段

在 `Residuum/搭建 HUD 与结算界面` 里多建一套。**不要新增菜单项。**

根节点 `Pause Canvas`，`sortingOrder = 250`——
**在主菜单（200）之上、渐变层（300）之下**：暂停菜单要盖住一切界面，
但渐变过场要盖住它。

子节点：

| 节点 | 类型 | 说明 | 连到 |
|---|---|---|---|
| `Panel` | `Image` | 铺满全屏，黑色 `PanelAlpha` | `_panelRoot` |
| `Panel/Box` | `Image` | 居中 460×220，深灰，**记得配 RectTransform** | 不连 |
| `Panel/Box/ResumeButton` | `Button` + 子 `TextMeshProUGUI` | 上方，260×56，文字「继续游戏」 | `_resumeButton` |
| `Panel/Box/QuitToMenuButton` | `Button` + 子 `TextMeshProUGUI` | 下方 20px，260×56，文字「返回主菜单」 | `_quitToMenuButton` |

`_panelRoot` 连 `Panel` 不是画布本身。建完 `Panel` 设为不激活。

`_playerControllerBehaviour` 连场景里的 `PlayerController`；
`_screenFader` 场景里有 `ScreenFader` 就连上，没有就跳过并警告。

沿用已有的 Undo 分组、`SerializedObject` 赋值、幂等复用、
`GetOrCreateUiChild` 的 localScale 重置。

## 明确不要做的

- 不要改 `GameManager`、`MainMenuUI`、`ResultScreenUI`、`JournalUI`、
  `PlayerController`、`ScreenFader`
- 不要往 `GameEvents.cs` 加任何东西
- 不要碰 `Time.timeScale`
- 不要做设置页、音量、画质、存档
- 不要自己写 `Cursor.lockState` / `Cursor.visible`
- 不要新增菜单项
- 不要自动把场景加进 Build Settings

## 需要新事件怎么办

不要自己加。写在最终回复里说明。本任务预期不需要。

## 验收标准

1. 编译通过，`git diff` 只有新增的 `PauseMenuUI.cs` 与
   `UISetupBuilder.cs` 两个文件
2. 跑 `Residuum/搭建 HUD 与结算界面`，出现 `Pause Canvas`，
   `Panel` 建完未激活，四个引用全部连好
3. 主菜单显示时按 `ESC` **没有反应**
4. 点「开始游戏」进入回合，按 `ESC`：菜单弹出，光标出现，玩家不能移动
5. 点「继续游戏」：菜单消失，光标锁回，玩家能动
6. 再按 `ESC` 弹出，点「返回主菜单」：渐暗后场景重载，回到主菜单
7. 重载后点「开始游戏」，一切正常——手上有手电、道具回到墙上、
   笔记本清空、鬼重新随机
8. 回合结束（结算界面弹出）时按 `ESC` 没有反应
9. 场景不在 Build Settings 里时，点「返回主菜单」控制台报一条明确的
   错误说明怎么加，游戏不崩
