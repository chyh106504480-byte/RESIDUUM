## 目标

关键路径最后一环。把所有模块串成一局完整游戏：
**开始 → 找证据 → 判定 → 撤离 → 结算**。

这一个做完，垂直切片的核心循环就成立了。

## 你是唯一的例外

`GameManager` 是架构铁律里**唯一允许持有全部模块引用**的类。
它负责初始化与编排，所以可以直接引用 `Residuum.World.RoomManager`、
`Residuum.Ghost.GhostAI` / `HuntController` 等具体类型。

其余铁律照旧：不改契约文件、可调数值 `[SerializeField]` + 中文 Tooltip、
订阅退订成对、Unity 6 API。

## 要做的文件

只产出 `Assets/_Project/Scripts/Core/GameManager.cs`，命名空间 `Residuum.Core`。

### StartRound()

按顺序：

1. 从 `[SerializeField] GhostDefinition[] _allGhosts` 中随机选一种鬼。
   `#if UNITY_EDITOR` 下提供 `[SerializeField] private GhostDefinition _forcedGhost`，
   非空时用它而不是随机——**演示时非常有用**
2. 把选中的 definition 注入 `_ghostAI.Definition`
3. 调 `GameEvents.SetGhostEvidence(definition.evidences)` 设置三个证据标志
4. 调 `RoomManager.Instance.SelectGhostRoom()`
5. **把鬼房中心与半径写进 `GameEvents`**：
   从 `RoomManager.Instance.GhostRoom` 取其 `Collider`（`GetComponent<Collider>()`，
   为空时 `Debug.LogError` 并中止开局），
   `GhostRoomCenter = collider.bounds.center`，
   `GhostRoomRadius = collider.bounds.extents.magnitude`。
   **这一步不能省** —— T07 鬼影书完全依赖这两个值判定，不写它永远不出书写
6. **传送鬼到鬼房内的随机点**：取 `GhostRoom.GetRandomPointInside()`，
   然后调 **`_ghostAI.WarpTo(点)`**。
   **绝对不要直接写 `transform.position`** —— 那会让 `NavMeshAgent` 与导航网格
   失去同步，鬼会原地不动或乱走。这是 T09 专门为你留的接口
7. 记录回合开始时间
8. 调 `GameEvents.RaiseRoundStart()` —— **放在最后**，此时所有状态已就位

### 回合中

- 订阅 `GameEvents.OnEvidenceFound(EvidenceType)`，把发现的证据记进一个
  `HashSet<EvidenceType>`，**同一项不重复计数**。
  暴露 `public int FoundCount { get; }`
- 订阅 `GameEvents.OnPlayerCaught`：立即以 `RoundResult.Died` 结束回合，
  并触发 `[SerializeField] private UnityEvent onPlayerDied` 供死亡演出连线
  （**不要自己写摄像机倒下的协程**，那是表现层）
- 玩家的判定：暴露 `public void SubmitGuess(GhostDefinition guess)`，
  记下来但**不立即结算**。笔记本 UI（T13）会调它

### EndRound()

玩家走到出口 trigger 时调用。出口用
`[SerializeField] private Collider _exitZone`，在 `Update` 里按可调间隔检查玩家
是否进入（或让外部调 `public void RequestEvacuate()`，**两种都要支持**）。

**猎杀期间不允许撤离**：`_huntController.IsHunting` 为 true 时拒绝，
并触发 `[SerializeField] UnityEvent onEvacuateBlocked` 供 UI 提示。

结算规则：

| 条件 | 结果 |
|---|---|
| 判定正确 **且** `FoundCount >= 2` **且** 理智 > 30 | `Perfect` |
| 判定正确 | `Success` |
| 判定错误或未判定 | `Survived` |
| 被抓 | `Died` |

理智从 `[SerializeField] private Residuum.Player.PlayerSanity _sanity` 的
`Current` 属性读（`GameManager` 是允许持有全部引用的例外）。为空时按 0 处理并告警。

最后调 `GameEvents.RaiseRoundEnd(result)`。

### 调试功能（`#if UNITY_EDITOR` 包裹）

- `_forcedGhost` 强制指定本局鬼种（见上）
- `[SerializeField]` 三个快捷键（默认 F9 / F10 / F11），用 Input System 读取：
  - F9 强制触发猎杀（调 `_huntController.ForceHunt()`）
  - F10 直接结束回合
  - F11 一键收集全部三种证据（直接往 `HashSet` 里塞，用于跳过取证流程演示）

**这三个键是 Henry 演示与验收的主要入口**，必须能用。

## 明确不要做的

- **不要**写死亡演出、结算界面、笔记本 UI —— 分别是表现层、T16、T13
- **不要**自己实现理智计算 —— 读 `PlayerSanity.Current`
- **不要**自己实现猎杀判定 —— 那是 T10
- **不要**碰契约文件
- **不要**用 `FindObjectOfType` / `FindFirstObjectByType` 找任何东西，
  全部 `[SerializeField]` 注入；确需按类型找时用 `FindAnyObjectByType`
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件

## 三条必须遵守的既有约定

1. **传送鬼一定要走 `GhostAI.WarpTo()`**，理由见上
2. **鬼房中心与半径必须写进 `GameEvents`**，否则 T07 鬼影书永远不出证据
3. **道具槽与鬼影书的连线时序**：`GhostWritingBook.onPlaced` 如果被连到会同步
   调用 `OnUnequip` 的逻辑上，会停掉书本刚启动的判定协程。你不负责连线，
   但如果你的代码里涉及道具槽整合，注意不要制造这个时序

## 验收标准

- 按 Play，`StartRound` 自动执行：Console 输出选中的鬼种名与鬼房名
- 鬼被传送到鬼房内且能正常巡逻（说明用了 `WarpTo` 而非直接改坐标）
- `GameEvents.GhostRoomCenter` / `GhostRoomRadius` 有非零值
- 三个证据标志与选中鬼种的 `evidences` 一致
- F9 触发猎杀，F11 一键集齐证据，F10 结束回合
- 猎杀期间走到出口拒绝撤离并触发 `onEvacuateBlocked`
- 判定正确 + 2 项证据 + 理智 > 30 → `Perfect`；判定正确 → `Success`；
  判定错误 → `Survived`；被抓 → `Died`
- `#if UNITY_EDITOR` 包裹的调试代码在非编辑器构建下不参与编译
- 所有数值 `[SerializeField]` + 中文 `[Tooltip]`
- 编译零错误
