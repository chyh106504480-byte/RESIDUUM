## 症状（阻断级）

**紫外线指纹这项证据现在永远采不到。**三种鬼里有两种持有它，
采不到就凑不齐两项证据，判定不出来——抽到那两只鬼整局就废了。

## 根因

`GhostAI` 有这个字段：

```csharp
[Tooltip("指纹生成请求；在 Inspector 中连接到 Fingerprint.SpawnAt。")]
public UnityEvent<Transform> onFingerprintRequest;
```

鬼交互时会 `onFingerprintRequest?.Invoke(target)`（`GhostAI.cs:796`）。

但 `Fingerprint.SpawnAt(Transform)` 是 **`public static`** 方法，
**UnityEvent 在 Inspector 里挂不上静态方法**——它的持久监听需要一个
具体的 UnityEngine.Object 实例作为目标。

所以这条线从设计上就接不通，场景里那个 UnityEvent 是
`m_Calls: []`，永远空着。

## 修法：加一个转发组件

**不要把 `SpawnAt` 改成非静态**——它是 public API，别的地方可能在用，
而且改签名会牵连更多。加一个可以挂在场景物体上的转发器即可。

## 只做一个文件

`Assets/_Project/Scripts/Evidence/FingerprintSpawner.cs`，
命名空间 `Residuum.Evidence`

```csharp
/// <summary>
/// 把 GhostAI.onFingerprintRequest 转发到静态的 Fingerprint.SpawnAt。
/// UnityEvent 的持久监听挂不了静态方法，所以需要这一层实例方法。
/// </summary>
public sealed class FingerprintSpawner : MonoBehaviour
{
    /// <summary>在 Inspector 里把 GhostAI.onFingerprintRequest 连到这里。</summary>
    public void Spawn(Transform target)
}
```

`Spawn` 的实现：

- `target` 为 null 时直接返回，**不报错**——`Fingerprint.SpawnAt` 自己
  已经会对 null 打警告，这里再打一次就是重复刷屏
- 否则调 `Fingerprint.SpawnAt(target)`
- 返回值忽略。`SpawnAt` 在目标身上找不到预布置的 `Fingerprint` 时
  会自己打一条警告，那是**预期行为**：不是每个鬼交互的目标都布置了指纹

**就这些。**不要加字段、不要加 `[SerializeField]`、不要订阅任何事件、
不要做冷却或去重——去重是 `Fingerprint.Activate()` 自己的事。

## 明确不要做的

- 不要改 `Fingerprint.cs`、`GhostAI.cs`、`UVLight.cs`
- 不要把 `SpawnAt` 改成实例方法
- 不要往 `GameEvents.cs` 加任何东西
- 不要自动在场景里挂这个组件
- 不要新建编辑器脚本或预制体
- 文件里不要有第二个类

## 需要新事件怎么办

不要自己加。写在最终回复里说明。本任务预期不需要。

## 验收标准

Henry 会建一个空物体挂上 `FingerprintSpawner`，
把 `GhostAI` 的 `On Fingerprint Request` 连到它的 `Spawn`。

1. 编译通过，`git diff` 只有新增的 `FingerprintSpawner.cs`（及其 meta）
2. `GhostAI` 的 `On Fingerprint Request` 里点 `+`，拖入挂着
   `FingerprintSpawner` 的物体后，方法下拉里**能看到
   `FingerprintSpawner` → `Spawn (Transform)`**，且在
   「Dynamic Transform」那一组里（这一条是本任务的全部意义）
3. 连好之后进 Play，鬼去交互一个布置了 `Fingerprint` 子物体的门或开关，
   拿紫外线灯照过去能看到指纹并采集到 UVFingerprint 证据
4. 鬼交互一个**没有**布置指纹的物体时，控制台出现一条来自
   `Fingerprint.SpawnAt` 的警告，游戏不受影响
