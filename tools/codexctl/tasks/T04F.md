## 背景

地图用的 Apartment Kit 模型**全是纯视觉网格，一个碰撞体都没有**。
实测场景里 `MeshCollider` 数量为 0，`BoxCollider` 只有我们自己生成的 8 个
`RoomVolume` 触发器和 1 个出口。

后果是**玩家走不动也上不了楼**：`CharacterController` 依赖碰撞体，
而楼梯、地板、墙全都没有。

鬼却能正常走——因为 NavMesh 烘焙用的是 `Use Geometry = Render Meshes`，
读渲染网格，跟碰撞体无关。这个不对称正是问题一直没被发现的原因。

几百个物件手工加不现实，做成菜单。

## 要做的文件

只产出 `Assets/_Project/Scripts/World/Editor/ColliderBuilder.cs`，
命名空间 `Residuum.World.Editor`，菜单 `Residuum/为选中对象批量加碰撞体`。

**先读 `Assets/_Project/Scripts/World/Editor/RoomVolumeBuilder.cs`**，写法保持一致：
`Undo` 分组、失败 `Undo.RevertAllDownToGroup` 整体回滚、结束 `MarkSceneDirty`。

### 做什么

对**选中物体及其全部子物体**递归处理：

- 找出所有带 `MeshFilter` 且 `sharedMesh` 非空的物体
- **已经有任何 `Collider` 的跳过**（不重复加，也不覆盖已有的）
- 给其余的加 `MeshCollider`，`convex = false`（静态几何体不需要 convex，
  且 convex 有 255 面上限，大网格会失败）
- 全部走 `Undo.AddComponent`，一次 Ctrl+Z 能整体撤销

### 必须跳过的东西

- **`sharedMesh` 为空**的 `MeshFilter`
- 名字里包含 `Light`、`Lamp`、`Particle`、`FX`、`Decal`、`Glass` 的物体
  （这些不该阻挡玩家；关键词列表写成 `private static readonly string[]`，
  匹配时忽略大小写）
- **本身或任意祖先已经挂了 `Residuum.World.RoomVolume` 的物体**
  —— 那些是我们的房间触发器，给它们加实体碰撞体会把玩家挡在房间外

### 报告

结束时一条 `Debug.Log` 说明：处理了多少个物体、新增了多少 `MeshCollider`、
跳过了多少（分别说明跳过原因的数量：已有碰撞体 / 无网格 / 命中关键词）。

数量超过 `private const int WarnThreshold = 2000` 时先 `Debug.LogWarning`
提示这会显著增加场景体积与物理开销，但仍然执行。

### 第二个菜单：`Residuum/移除选中对象的碰撞体`

对选中物体及子物体，移除所有 `MeshCollider`（**只移除 MeshCollider**，
不碰 `BoxCollider` / `CapsuleCollider`，避免误删 `RoomVolume` 的触发器与玩家的
碰撞体）。同样走 `Undo`，结束报告移除了多少个。

这个菜单是给「加错了想反悔」用的，Ctrl+Z 之外的第二道保险。

## 明确不要做的

- **不要**改任何运行时脚本
- **不要**碰契约文件
- **不要**给 `RoomVolume` 所在物体或其子物体加实体碰撞体
- **不要**把 `MeshCollider` 设成 `convex`
- **不要**自动烘焙 NavMesh，**不要**自动保存场景
- **不要**尝试判断哪些墙该有碰撞体哪些不该 —— 只按上面的跳过规则机械处理
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件

## 验收标准

- 选中 `Structure_02`（整栋楼），执行菜单后 Console 报出处理与跳过的数量
- 进 Play 后玩家能在地板上行走、被墙挡住、**能走上楼梯到二楼**
- `RoomVolume` 仍然是触发器，玩家能自由进出房间（没有被实体碰撞体挡住）
- 灯光、粒子等命中关键词的物体没有被加碰撞体
- 再次执行菜单不重复添加（已有碰撞体的被跳过）
- 一次 Ctrl+Z 能撤销整批添加
- `Residuum/移除选中对象的碰撞体` 能清掉 MeshCollider 且不影响 RoomVolume 触发器
- 编译零错误
