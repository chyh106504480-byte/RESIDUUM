## 背景

两个实测问题，都在 `GhostAI` 的巡逻点处理上。

**一、随机抽点大量抽到脚边。**
现在的实现是 `Random.Range(0, _roamPoints.Length)` 均匀抽取，抽到离鬼很近的点时
鬼几乎不移动，表现成「一直在一小块区域打转」。

**二、巡逻点摆错高度时要 Play 后才发现。**
实测有一个点被摆到 `Y = 9.11`（三楼，二楼地面在 `Y ≈ 4.16`），
每次抽中就 `SetDestination` 失败，一局刷了 93 条警告。
`SetDestination` 的返回值检查起了作用，但**问题应该在开局就暴露**，
而不是靠人从几十条重复警告里读坐标。

## 要改的文件

只改 `Assets/_Project/Scripts/Ghost/GhostAI.cs`。

### 改动一：巡逻点选择加最小距离

新增 `[SerializeField] private float _minimumRoamDistance = 8f;`
带中文 `[Tooltip]`（说明「随机巡逻点与鬼当前位置的最小距离，避免抽到脚边的点
导致鬼原地打转」）。

选点逻辑改为：

1. 遍历 `_roamPoints`，收集**非空**且**与鬼当前位置距离 ≥ 最小距离**的候选
2. **尽量排除上一次去过的那个点**（记录上次目标的引用或下标）；
   若排除后没有候选就不排除
3. 从候选里**随机取一个**
4. **没有任何候选时**（所有点都太近）：退而取**距离最远**的那个非空点，
   **不要返回 false、不要让鬼停下**——保证巡逻永远能继续
5. 全部为空时保持现有行为（回退到自身位置并返回 false）

用平方距离比较，不要每次开方。

### 改动二：开局校验巡逻点

在 `Start`（或首次进入 Roam 前）对每个非空巡逻点做一次
`NavMesh.SamplePosition` 校验（最大距离用 `[SerializeField]` 可调，默认 `2`）：

- 映射失败的点，**`Debug.LogError` 明确报出该点的物体名与世界坐标**，
  并说明它不在导航网格上、鬼永远到不了
- 把这些点**从候选集合中永久剔除**，避免运行时反复失败刷屏
- 校验结果只在开局报一次，不要每帧或每次选点都报

如果**所有**巡逻点都校验失败，额外 `Debug.LogError` 提示
「没有任何可用的巡逻点，鬼将无法巡逻」。

## 明确不要做的

- **不要**改状态机结构、Idle/Interact/Hunt 的任何逻辑
- **不要**改推门、视线检测、脚印、冲刺的实现
- **不要**移除 `SetDestination` 返回值检查与 `isOnNavMesh` 检查
  —— 那五条 NavMesh 硬性要求一条都不能少
- **不要**自动修正巡逻点的位置 —— 摆在哪是人的关卡设计决策，只报错
- **不要**引用 `Residuum.World` 的任何类
- **不要**碰契约文件
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件的改动

## 验收标准

- 巡逻点摆在不同房间时，鬼**不会反复去离自己最近的那个点**，
  连续几次 Roam 的目标明显分散
- 所有点都在最小距离内时鬼仍然会移动（取最远的那个），不会卡住不动
- 把一个巡逻点摆到导航网格外（例如三楼高度），**开局立刻 `LogError`
  报出该点的名字与坐标**，且运行中不再反复刷 `SetDestination` 失败警告
- 全部巡逻点都无效时有明确的中文错误提示
- `_minimumRoamDistance` 可在 Inspector 调整并立即生效
- 除 UnityEngine / UnityEngine.AI / UnityEngine.Events / System 外
  只 `using Residuum.Core;`
- 编译零错误
