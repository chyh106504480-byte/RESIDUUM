## 背景

十二个模块的代码都过了终审，但**行为一次都没验证过**——场景里还没有
`GameManager`、`HuntController`、鬼、出口、安全区。

`GameManager` 要注入的引用有九个之多，手工连一遍容易漏，漏一个就是运行时
`LogError` 然后花时间排查。做成菜单，与 `Residuum/搭建玩家装配`、
`Residuum/搭建测试台`、`Residuum/搭建鬼装配` 同一性质。

## 要做的文件

只产出 `Assets/_Project/Scripts/Core/Editor/RoundSetupBuilder.cs`，
命名空间 `Residuum.Core.Editor`，菜单 `Residuum/搭建回合装配`。

**先读 `Assets/_Project/Scripts/Ghost/Editor/GhostSetupBuilder.cs`**，
写法与它保持一致：`Undo` 分组、`SerializedObject` 注入、`FindProperty` 为 null
时抛 `InvalidOperationException` 带中文说明、失败 `Undo.RevertAllDownToGroup`
整体回滚、结束 `MarkSceneDirty`、幂等。

### 前置检查（缺任何一项都要报明确中文错误并中止，不创建任何东西）

按顺序检查，缺什么就提示先执行哪个菜单：

- 场景里有 `Residuum.Player.PlayerController` —— 否则提示先执行 `Residuum/搭建玩家装配`
- 场景里有 `Residuum.Ghost.GhostAI` —— 否则提示先执行 `Residuum/搭建鬼装配`
- 场景里有 `Residuum.World.RoomManager` —— 否则提示先手动创建并摆好 `RoomVolume`
- 三个鬼种资产存在于 `Assets/_Project/ScriptableObjects/Ghosts/` ——
  否则提示先执行 `Residuum/创建三种鬼资产`

查找场景组件统一用 `FindAnyObjectByType<T>(FindObjectsInactive.Include)`。
**不要用 `FindObjectOfType` 或 `FindFirstObjectByType`，两者在 Unity 6 都已弃用。**

### 要生成的东西

全部挂在一个名为 `RoundSetup` 的空物体下，便于整体删除。

**1. `RoundSetup/GameManager`**
挂 `Residuum.Core.GameManager`，用 `SerializedObject` 注入（字段名已核对，照抄）：

| 字段 | 注入什么 |
|---|---|
| `_allGhosts` | 三个鬼种资产，用 `AssetDatabase` 按 `t:GhostDefinition` 搜索目录取得 |
| `_ghostAI` | 场景里的 `GhostAI` |
| `_huntController` | 下面新建的那个 |
| `_sanity` | 玩家身上的 `PlayerSanity`（没有则先 `Undo.AddComponent` 挂一个） |
| `_player` | `PlayerController` 所在物体的 `transform` |
| `_exitZone` | 下面新建的出口 Collider |

`_forcedGhost` 留空（那是演示时手动指定用的），三个快捷键字段保持默认值不动。

**2. `RoundSetup/HuntController`**
挂 `Residuum.Ghost.HuntController`，注入 `_ghostAI` 指向场景里的 `GhostAI`。

**3. `RoundSetup/ExitZone`**
空物体 + `BoxCollider`，`isTrigger = true`，`size = (3, 3, 3)`，
位置放在**玩家当前位置**（人之后手动挪到一楼大门口）。
`Debug.Log` 提示这是占位位置、需要手动挪到出口。

**4. `RoundSetup/SafeZone`**
空物体 + `BoxCollider`，`isTrigger = true`，`size = (10, 4, 10)`，
同样放在玩家当前位置。用 `SerializedObject` 注入到 **`PlayerSanity` 的安全区字段**
——**字段名请先读 `PlayerSanity.cs` 确认**，不要凭猜。
`Debug.Log` 提示需要手动挪到一楼 Lobby 并调整大小。

### 幂等

场景已有 `RoundSetup` 时不重复创建，`Debug.Log` 说明并选中它，直接返回。

## 关于跨模块引用

本文件在 `Scripts/Core/Editor/` 下，会引用 `Residuum.Ghost`、`Residuum.Player`、
`Residuum.World` 的具体类型。**编辑器装配工具允许这样做**，理由与 T01H / T01I /
T09B 相同：把各模块组件在场景里连起来正是它的职责。
沿用它们的做法，**用全限定名而不是 using**。

## 明确不要做的

- **不要**改任何运行时脚本
- **不要**碰契约文件
- **不要**创建 `RoomVolume` 或巡逻点 —— 那是人的关卡设计决策
- **不要**自动摆放出口与安全区的最终位置 —— 只给占位并提示
- **不要**烘焙 NavMesh，**不要**自动保存场景
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件

## 验收标准

- 在已执行过玩家装配、鬼装配、且有 `RoomManager` 的场景执行菜单，
  层级出现 `RoundSetup`，其下有 `GameManager`、`HuntController`、
  `ExitZone`、`SafeZone`
- `GameManager` 的六个引用字段全部非空，`_allGhosts` 长度为 3
- `HuntController._ghostAI` 非空
- `PlayerSanity` 的安全区字段指向 `SafeZone` 的 Collider
- 缺少玩家装配 / 鬼装配 / RoomManager / 鬼种资产时，各自报出**指名道姓**的
  中文错误（说清该先执行哪个菜单），且不创建任何东西
- 再次执行菜单不重复创建
- 一次 Ctrl+Z 能撤销整个回合装配
- 编译零错误
