## 目标

玩家按键打开笔记本，看到「三项证据的状态」与「三种鬼的推理表」，
并在表里点一个按钮把判定提交出去。

**这是整个游戏回合唯一的胜负输入。**`GameManager.SubmitGuess()` 已经写好但
目前没有任何地方调用它——玩家现在无法赢下一局。本任务补上这一环。

## 要做的文件

**只做这一个**：`Assets/_Project/Scripts/UI/JournalUI.cs`，命名空间 `Residuum.UI`。

uGUI + TextMeshPro。所有界面引用一律 `[SerializeField]` 在 Inspector 里注入，
**不要在代码里 new 任何 UI 对象**（搭建界面是另一个任务）。

## 跨模块怎么处理（这一段照做，别自己发挥）

`JournalUI` 只允许 `using UnityEngine`、`using System.Collections.Generic`、
`using TMPro`、`using UnityEngine.UI`、`using Residuum.Core`、
`using Residuum.Evidence`。

引用其它模块的具体类时**一律用全限定名 + `[SerializeField]` 注入**，
不要加 using：

```csharp
[Tooltip("场景里的 EvidenceManager")]
[SerializeField] private Residuum.Evidence.EvidenceManager _evidenceManager;

[Tooltip("三种鬼的定义资产，用于绘制推理表。顺序即表格行序")]
[SerializeField] private Residuum.Ghost.GhostDefinition[] _allGhosts;
```

## 开关笔记本与「谁管光标」

```csharp
[SerializeField] private UnityEngine.InputSystem.Key _toggleKey
    = UnityEngine.InputSystem.Key.Tab;
```

按键检测用 `UnityEngine.InputSystem.Keyboard.current`，参照
`GameManager.HandleEditorShortcuts` 的写法（`wasPressedThisFrame`，
并对 `Keyboard.current == null` 做保护）。

**光标与移动控制不要自己写。**场景里的 `PlayerController` 已经在
`OnEnable` 里锁光标 + 启用输入、在 `OnDisable` 里解锁光标 + 停用输入。
笔记本只需要开关那个组件：

```csharp
[Tooltip("拖入玩家身上的 PlayerController 组件。笔记本打开时会禁用它，" +
         "从而同时停掉移动、视角与光标锁定；关闭时恢复")]
[SerializeField] private MonoBehaviour _playerControllerBehaviour;
```

字段类型必须是 `MonoBehaviour` 而不是 `PlayerController`，这样不需要
引用 Player 模块。打开时 `enabled = false`，关闭时 `enabled = true`。
`_playerControllerBehaviour` 为 null 时不要报错，只跳过这一步。

**不要自己写任何 `Cursor.lockState` / `Cursor.visible`。**两处一起改光标
必然打架。

## 猎杀期间必须强制关闭

订阅 `GameEvents.OnHuntStart`，笔记本开着就立刻关掉，并且在猎杀期间
按开关键无效。否则玩家可以靠开笔记本冻结移动来躲猎杀。
`GameEvents.OnHuntEnd` 之后恢复可开。

同样订阅 `GameEvents.OnRoundEnd`，回合结束时强制关闭。

## 界面三块

### 左：证据清单，三行

每行一个 `TextMeshProUGUI`（Inspector 注入 `TextMeshProUGUI[] _evidenceLabels`，
长度 3，顺序固定为 EMF5 / UVFingerprint / GhostWriting），外加一个
可点击的 `Button[] _evidenceRuleButtons`（同样长度 3）。

三态显示，颜色与前缀都做成 `[SerializeField]`：

| 状态 | 判据 | 前缀默认 | 颜色默认 |
|---|---|---|---|
| 已发现 | `_evidenceManager.IsFound(type)` | `"✓ "` | 白 |
| 已排除 | `_evidenceManager.IsRuled(type)` | `"✗ "` | `(0.55, 0.2, 0.2)` |
| 未知 | 以上都不是 | `"  "` | `(0.45, 0.45, 0.45)` |

点击第 i 个按钮：
- 该项已发现 → 什么都不做（已发现的不能排除）
- 该项已排除 → 调 `_evidenceManager.ClearRuled(type)`
- 未知 → 调 `_evidenceManager.MarkEvidenceRuled(type)`

### 右：3×4 推理表

行 = `_allGhosts` 的每一项，列 = 鬼名 + 三项证据。

Inspector 注入 `TextMeshProUGUI[] _ghostNameLabels`（长度 = 鬼数）
与 `TextMeshProUGUI[] _ghostEvidenceCells`（长度 = 鬼数 × 3，按行优先排列）。

- 鬼名显示 `definition.ghostName`
- 每格：`definition.HasEvidence(type)` 为真显示 `"✓"`，否则 `"—"`
  （两个字符串都做成 `[SerializeField]`）
- **该鬼已被排除出候选**（不在 `_evidenceManager.Candidates` 里）时，
  整行的鬼名与三格一起变暗：颜色乘 `[SerializeField] Color _ruledOutRowTint`，
  默认 `(1, 1, 1, 0.35f)`

### 底：判定按钮

`Button[] _guessButtons`，长度 = 鬼数，第 i 个对应 `_allGhosts[i]`。

点击后触发：

```csharp
[System.Serializable]
public class GhostGuessEvent : UnityEngine.Events.UnityEvent<Residuum.Ghost.GhostDefinition> { }

[Tooltip("在 Inspector 里连到 GameManager.SubmitGuess")]
public GhostGuessEvent onGuessSubmitted = new GhostGuessEvent();
```

必须声明成上面这样的具名子类，否则泛型 UnityEvent 在 Inspector 里不显示。
**不要在代码里直接引用 GameManager**，连线由 Henry 在 Inspector 完成。

提交后：把被选中那一行高亮（`[SerializeField] Color _selectedGuessTint`，
默认 `(0.35, 0.85, 0.4, 1)`），并且允许改判——再点另一个按钮就换成新的。
回合开始时清掉高亮。

## 刷新时机

不要每帧刷新。只在这四个时刻重建整个界面：

1. 笔记本被打开时
2. `_evidenceManager.onCandidatesChanged` 触发时（在 `OnEnable` 里
   用 `AddListener` 订阅，`OnDisable` 里 `RemoveListener`）
3. `GameEvents.OnEvidenceFound` 触发时
4. `GameEvents.OnRoundStart` 触发时

笔记本关着的时候也要照常更新内部状态，但可以跳过实际的 UI 写入。

## Awake 校验

- `_evidenceManager` 为 null → `Debug.LogError` 并 `enabled = false`
- `_allGhosts` 为空、或长度与 `_ghostNameLabels`、`_guessButtons` 对不上、
  或 `_ghostEvidenceCells.Length != _allGhosts.Length * 3` → `Debug.LogError`
  并 `enabled = false`
- `_evidenceLabels` 或 `_evidenceRuleButtons` 长度不是 3 → 同上

报错信息里写清楚期望长度与实际长度。

## 明确不要做的

- **不要写任何创建 UI 层级的代码**，不要 `new GameObject`、不要 `AddComponent`
- 不要碰 `Time.timeScale`（不做暂停，猎杀期间时间必须继续走）
- 不要改 `PlayerController`、`GameManager`、`EvidenceManager` 里的任何一行
- 不要自己写 `Cursor.lockState` / `Cursor.visible`
- 不要新建 `.asset`、`.prefab` 或编辑器脚本
- 不要在 `Residuum.UI` 里 using `Residuum.Ghost` 或 `Residuum.Player`
- 不要实现存档、翻页、多页笔记本

## 需要新事件怎么办

不要自己往 `GameEvents.cs` 里加。写在最终回复里说明需要什么签名和理由。
本任务预期不需要新事件。

## 验收标准

Henry 会在 Unity 里逐条点：

1. 按 Tab 打开笔记本，鼠标光标出现，玩家不能移动也不能转视角；
   再按 Tab 关闭，光标消失，移动与视角恢复
2. 开局时三项证据全是灰色「未知」，推理表三行全亮，无行变暗
3. 点第一项证据的排除按钮，该行变成 `✗` 且变红；持有该证据的两只鬼整行变暗，
   剩一只鬼是亮的
4. 再点一次同一个按钮，排除被撤销，三行恢复全亮
5. 用 F11（`GameManager` 的调试快捷键）收集全部证据后打开笔记本，
   三项全变 `✓`，推理表只剩一行是亮的
6. 已发现的证据点排除按钮没有任何反应，控制台不刷屏
7. 点底部某个判定按钮，那一行高亮成绿色；点另一个按钮，高亮转移
8. 笔记本开着的时候按 P 强制触发猎杀，笔记本立刻自动关闭，
   玩家恢复可移动；猎杀期间按 Tab 打不开
9. 猎杀结束后 Tab 恢复可用
10. 故意把 `_ghostEvidenceCells` 数组长度改成 8，进 Play 时控制台报一条
    写明期望 9 实际 8 的错误，组件被禁用，不抛空引用
