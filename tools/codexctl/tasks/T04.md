## 目标

把关卡切成若干「房间」，让系统知道玩家在哪个房间、鬼房是哪个，
并按到鬼房的距离产出一个温度读数。

## 契约（已存在，不许改）

```
Assets/_Project/Scripts/Core/GameEvents.cs
```

本任务需要的事件**已经加进契约、可以直接用**：

```csharp
// 玩家所处位置的温度读数变化时广播，单位摄氏度。HUD（T14）订阅它。
GameEvents.RaisePlayerTemperatureChanged(float celsius);
```

**注意**：不要自己在 `RoomManager` 上声明 `public event Action<float> OnPlayerTemperatureChanged`。
温度要给 UI 看，UI 不认识 `RoomManager`，一律走事件总线。

## 要做的文件

### 1. `Assets/_Project/Scripts/World/RoomVolume.cs`

命名空间 `Residuum.World`。挂在每个房间的 `BoxCollider`（`isTrigger = true`）上。

- `[SerializeField]` 可调项（全部带中文 `[Tooltip]`）：
  - 房间中文名，默认 `"未命名房间"`
  - 房间 ID（string），用于日志与调试
  - 是否可作为鬼房候选（bool），默认 `true`
  - 玩家层 `LayerMask`（判定进出用，默认 `~0`）
- 检测玩家进出（`OnTriggerEnter` / `OnTriggerExit`，按玩家层过滤）
- `public bool HasPlayer { get; private set; }`
- `public event Action<RoomVolume, bool> OnPlayerPresenceChanged`
  —— 这个**保留为本类的公开事件**，因为订阅方 `RoomManager` 与它同属
  `Residuum.World`，同模块通信不需要经过事件总线
- `public Vector3 GetRandomPointInside()`：返回房间内地面上的随机点。
  用 `NavMesh.SamplePosition`（`UnityEngine.AI`）把随机点吸附到导航网格上。
  **采样失败时**（还没烘焙 NavMesh 时必然失败）不要抛异常、不要死循环重试：
  返回 Collider 中心并 `Debug.LogWarning` 说明原因。采样最大距离做成
  `[SerializeField]`，默认 `2`
- `OnDrawGizmos`：画出房间边界线框 + 房间中文名（用 `UnityEditor.Handles.Label`，
  必须用 `#if UNITY_EDITOR` 包裹，否则打包会编译失败）。
  是鬼房候选的房间用不同颜色区分

### 2. `Assets/_Project/Scripts/World/RoomManager.cs`

命名空间 `Residuum.World`。场景单例（`public static RoomManager Instance { get; private set; }`，
在 `Awake` 赋值，重复实例 `Debug.LogError` 并销毁自己）。

- 启动时收集场景中所有 `RoomVolume`：
  用 `FindObjectsByType<RoomVolume>(FindObjectsInactive.Include)`
  —— **不要**传 `FindObjectsSortMode`（该重载在 Unity 6 已弃用），
  **不要**用 `FindObjectsOfType`
- 订阅每个 `RoomVolume.OnPlayerPresenceChanged`，维护
  `public RoomVolume CurrentPlayerRoom { get; private set; }`。
  `OnEnable` 订阅、`OnDisable` 全部退订，严格配对
- `public void SelectGhostRoom()`：从「可作为鬼房候选」的房间里随机选一个，
  写入 `public RoomVolume GhostRoom { get; private set; }`，并 `Debug.Log` 选中结果。
  候选为空时 `Debug.LogError` 并保持 `GhostRoom` 为 null，不要抛异常
- 温度模拟 `public float GetTemperatureAt(Vector3 pos)`：
  - `[SerializeField]` 基础室温，默认 `12`（摄氏度）
  - `[SerializeField]` 鬼房中心温度，默认 `-2`
  - `[SerializeField]` 影响半径，默认 `6`
  - 按到 `GhostRoom` 中心的距离在两者之间线性插值，超出半径返回基础室温
  - `GhostRoom` 为 null 时直接返回基础室温
- 温度广播：`[SerializeField]` 更新间隔默认 `0.5` 秒，用**缓存的**
  `WaitForSeconds` 协程（不要在循环里 `new`），每次取玩家位置算温度，
  **只在读数变化超过可调阈值（默认 `0.1` 度）时**才调用
  `GameEvents.RaisePlayerTemperatureChanged(t)`，避免每 0.5 秒无意义刷屏
- 玩家位置从 `[SerializeField] private Transform _player` 注入，**不要**去场景里找玩家
- 协程必须在 `OnDisable` 中 `StopCoroutine` / `StopAllCoroutines`

## 明确不要做的

- **不要做温度计道具** —— 切片只有 3 种证据（EMF / 紫外线指纹 / 鬼影书写），
  温度是氛围与提示，不是证据，做成道具是白干
- **不要做房间灯光管理** —— T12 理智系统自己用 `OverlapSphere` 找灯，不靠房间
- **不要做温度 UI** —— 那是 T14，你只负责广播
- **不要**把鬼传送进鬼房 —— 那是 T15 `GameManager` 的职责，
  你只负责 `SelectGhostRoom()` 和暴露 `GhostRoom`
- **不要**引用 `Residuum.Ghost` 或 `Residuum.Player` 的任何类
- 只产出上面两个文件

## 验收标准

- Scene 视图里能看到每个房间的线框和中文名；鬼房候选房间颜色不同
- 运行时 `SelectGhostRoom()` 随机选中一个房间并打出 Debug.Log，多次运行结果不同
- 玩家走进/走出房间，`CurrentPlayerRoom` 正确切换
- 走近鬼房温度读数下降，走远回到 12 度；读数不抖动、不每帧刷日志
- 场景**没有烘焙 NavMesh 时** `GetRandomPointInside()` 不报错、不卡死，
  只打一条 Warning 并返回房间中心
- 两个文件除 UnityEngine / UnityEngine.AI / System 外，只允许 `using Residuum.Core;`
- 所有数值 `[SerializeField]` + 中文 `[Tooltip]`，零硬编码魔法数
- 编译零错误
