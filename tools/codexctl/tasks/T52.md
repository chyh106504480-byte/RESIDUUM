## 目标

鬼影书左键放到地上后，准星瞄准它按 `E` 没有任何反应，捡不回来。
本任务修好它，**只改一个文件**。

## 根因（已经查清，不要再自己推断）

场景里的层级是这样的：

```
HandAnchor
└── BookRoot            ← GhostWritingBook 组件挂在这里
    └── Held_NoteBook   ← 纯视觉模型，只有 Transform
```

`BookRoot` 这个 GameObject 上**只有 Transform 和 GhostWritingBook 本身**，
整条子树没有任何 `Collider`。

`OnPrimaryUse()` 里执行 `transform.SetParent(null, true)`，
被放到地上的正是 `BookRoot` 这条无碰撞体的链。

而 `PlayerInteractor.DetectInteractable()` 是这样找交互目标的：

```csharp
Physics.Raycast(..., _interactionMask, QueryTriggerInteraction.Collide)
...
hit.collider.GetComponentInParent<IInteractable>()
```

**必须先由射线命中一个 Collider，才会去取 IInteractable。**
地上的书没有碰撞体，射线永远打不到它，
所以 `CanInteract => IsPlaced` 已经返回 `true` 也没用，
`Interact()` 根本没有机会被调用。

不是状态机的问题，`IsPlaced` / `RestoreHeldPose` 这些逻辑都是对的，
**缺的就是一个碰撞体**。

## 要改的文件

`Assets/_Project/Scripts/Evidence/GhostWritingBook.cs` —— 只有这一个。

### 加一个字段

```csharp
[Tooltip("放到地上时启用的碰撞体，用来被交互射线打到。留空则在 Awake 按子物体 Renderer 的包围盒自动补一个 BoxCollider。")]
[SerializeField] private Collider _placedCollider;
```

### 碰撞体必须是 trigger

`PlayerInteractor` 的射线用的是 `QueryTriggerInteraction.Collide`，
**能打到 trigger**。设成 trigger 的好处是不会物理阻挡玩家——
一本躺在地上的书不该把玩家顶起来，也不该影响鬼的寻路。

所以：不论是 `[SerializeField]` 指定的还是自动生成的，
在启用它之前都要确保 `isTrigger = true`。

### 自动补碰撞体（`_placedCollider` 为空时）

在 `Awake` 里做，步骤：

1. `GetComponentsInChildren<Renderer>(true)` 收集所有 Renderer
2. 一个都没有 → `Debug.LogWarning` 说明「鬼影书没有可用于生成碰撞体的
   Renderer，放置后将无法被捡回，请手动指定 _placedCollider」，然后返回，
   **不要抛异常**
3. 把这些 Renderer 的 `bounds`（世界空间）合并成一个总包围盒
4. 在 `BookRoot` 自己身上 `gameObject.AddComponent<BoxCollider>()`
5. 用 `transform.InverseTransformPoint(总包围盒.center)` 换算出 `center`；
   `size` 用总包围盒 `size` 除以 `transform.lossyScale` 逐分量换算到局部空间
6. `isTrigger = true`

包围盒太小的时候按 `E` 很难瞄准，所以生成后给 `size` 一个下限：
每个分量至少 `0.12f`（米）。写成一个 `private const float MinimumColliderSize = 0.12f;`。

**注意 `lossyScale` 分量可能为 0**，除之前要判断，为 0 时该分量直接用
包围盒原值，不要产生 `NaN` / `Infinity`。

### 启用与禁用的时机

| 时机 | 碰撞体 |
|---|---|
| `Awake` 结束时 | `enabled = false` |
| `OnPrimaryUse()` 放置**成功**之后 | `enabled = true` |
| `OnPrimaryUse()` 里 `TryFindGround` 失败提前返回 | 保持 `false`，不要动 |
| `Interact()` 捡回时 | `enabled = false` |
| `HandleRoundStart()` 回合重置 | `enabled = false` |

写成一个私有方法 `SetPlacedColliderActive(bool active)` 统一处理，
里面对 `_placedCollider == null` 做保护直接返回。

顺序上，`OnPrimaryUse` 里请在 `IsPlaced = true` 之后、`onPlaced?.Invoke()`
之前启用；`Interact` 里请在 `IsPlaced = false` 之后、`RestoreHeldPose()`
之前禁用。

### 为什么手持时必须是禁用的

书在手上时紧贴摄像机。碰撞体开着的话，玩家自己的交互射线第一个打到的
就是手里的书，**别的东西全都交互不了了**。这是这个任务最容易踩的坑。

## 明确不要做的

- 不要改场景 `Blockout.unity`，**一行都不要动**（有别的工作正在改它）
- 不要改 `PlayerInteractor.cs`、`ItemSlotSystem.cs`、`WorldItem.cs`
- 不要去动那个独立的 `NoteBook` 世界实体（带 BoxCollider + Rigidbody 的那个），
  它归 `ItemSlotSystem` 的丢弃流程管，和本任务无关
- 不要给鬼影书加 `Rigidbody`，也不要让它掉落或滚动。
  `TryFindGround` 已经把它精确贴到地面了
- 不要改 `IsPlaced` / `HasWriting` 的既有语义
- 不要改写字概率、检查间隔这些数值
- 不要往 `GameEvents.cs` 加任何东西
- 不要新增 Editor 菜单项

## 验收标准

1. 编译通过，`git diff` 里**只有** `GhostWritingBook.cs` 一个文件
2. 场景不跑搭建工具、不做任何手动配置的情况下，`_placedCollider`
   留空也能工作——进游戏后书上自动多出一个 `BoxCollider`，`isTrigger` 勾着
3. 手里拿着鬼影书时，准星瞄准门 / 灯开关，`[E] 开门` 一类提示**照常出现**
   （这条不过说明碰撞体没关掉，是最要命的回归）
4. 左键把书放到地上，准星瞄准它，出现 `[E] 捡回鬼影书`
5. 按 `E`，书回到手上，HUD 槽位显示正常
6. 放下、捡回，反复三次都正常
7. 书放在地上时走过去，玩家**不会被绊住或顶起来**
8. 书放在地上等鬼写字，写完后仍然能被捡回
9. 一局结束再开一局，书回到初始状态，碰撞体是关的
