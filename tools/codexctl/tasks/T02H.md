## 背景

`DoorConverter` 现在对**选中物体及其子物体递归查找每一个 `MeshFilter`，
逐个转成一扇门**。但资产包的一扇门是由多个网格拼成的：门板、门把手、玻璃、
门牌、栏杆各是独立的 `MeshFilter`。

实测转换后场景里出现了这些铰链：

```
Door.001_Hinge        ← 门板
Handle_Door.001_Hinge ← 门把手
Glass.001_Hinge       ← 玻璃
Plate_Hinge           ← 门牌
Bars_Hinge            ← 栏杆
```

一扇门被拆成五扇，各自绕自己的边缘转。玩家按 E 命中的可能是门把手那个 `Door`，
转的只是把手——**门打不开**。

## 要改的文件

只改 `Assets/_Project/Scripts/World/Editor/DoorConverter.cs`。

### 核心改动：一次选择 = 一扇门

把「递归每个 MeshFilter 各转一扇」改为「**当前选中的全部物体合起来算作一扇门**」：

1. 取 `Selection.gameObjects` 里所有场景物体（**不要**再递归展开成
   每个 `MeshFilter` 各自处理）
2. 计算这些物体**及其子物体**的 `Renderer.bounds` **并集**，作为整扇门的包围盒
3. 按现有逻辑在包围盒的一侧边缘建**一个** `_Hinge` 空物体
   （命名用第一个选中物体的名字）
4. 把**所有选中物体**（保持各自的子层级不变）`Undo.SetTransformParent`
   到这个铰链下，**保持世界坐标不变**
5. 铰链上挂**一个** `Door`，`_hinge` 指向自身
6. 铰链上加**一个** `NavMeshObstacle`，`carving = true`，尺寸按整扇门的包围盒
7. 给**还没有 `Collider`** 的门板网格各加一个贴合的 `BoxCollider`（非 trigger）
   —— 碰撞体仍然逐个加，因为玩家要撞到实体；但 `Door` 只有一个

### 跳过规则不变

- 名字含 `Frame` / `Frames` 的物体不纳入（门框不跟着转）
- 已经在带 `Door` 的层级下的跳过
- 没有选中任何场景物体时报明确中文错误

### 报告

一条 `Debug.Log`：合并了几个物体成一扇门、铰链叫什么、跳过了几个门框。
与 `RoomVolumeBuilder` 的多选合并提示保持一致的措辞风格。

## 明确不要做的

- **不要**改 `Door.cs` 或任何运行时脚本
- **不要**改铰链位置的计算逻辑（世界包围盒较长轴、min/max 边、底部高度）
- **不要**改左右两个菜单的结构
- **不要**改门板的世界位置、旋转、缩放
- **不要**用 `GetInstanceID()` 或 `GetEntityId()` 做去重
  —— 两者在 Unity 6.5 都触发 CS0619，用 `HashSet<GameObject>`
- **不要自己启动 Unity**（见 AGENTS.md）
- 只产出这一个文件的改动

## 验收标准

- 选中一扇门的全部零件（门板 + 把手 + 玻璃等），执行菜单后**只生成一个**
  `_Hinge`，所有零件都挂在它下面，**外观与世界位置完全不变**
- 铰链上只有**一个** `Door` 和**一个** `NavMeshObstacle`
- 进 Play 走到门前轻点 `E`，**整扇门（含把手玻璃）一起绕侧边转开**
- 门框没有被纳入
- 再次对同一扇门执行不重复转换
- 一次 Ctrl+Z 能撤销
- 编译零错误
